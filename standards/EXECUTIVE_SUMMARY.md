# Executive Summary — The Ka0s Addon Standard

**One-page TL;DR of the standard.** Full text: [`STANDARDS.md`](STANDARDS.md). Scaffolding pack for new addons (fetched at runtime, never stored in the addon): [`NEW_ADDON_CONTEXT.md`](NEW_ADDON_CONTEXT.md). Each addon is audited **in its own repo** via `/wow-addon:standards-audit` — see the [`../AUDIT.md`](../AUDIT.md) playbook.

---

## What this is

The house standard for the Ka0s World of Warcraft addon collection — the canonical set of rules for tech stack, libraries, design patterns, code structure, naming, packaging, localization, settings, slash commands, debug, and docs. It codifies what already works across the collection and closes the gaps, so every future addon is **born compliant**.

**Substrate:** Ace3. **License:** MIT (always). **Scope:** Retail only. Every addon must be built to this standard and **reference it in three places** — the TOC `X-Standard` field, the README standard badge, and the root `CLAUDE.md` "Standards compliance (read first)" section — so <https://github.com/tusharsaxena/WowAddonStandards> is always in the addon's project memory and context (documentation-§6). The standard is versioned; see the changelog at the top of `STANDARDS.md` (current: **v2.21.0**, 2026-08-04).

## The six patterns it makes canonical

These were validated against the Ka0s collection and the broader ecosystem (see [`INDUSTRY_RESEARCH.md`](INDUSTRY_RESEARCH.md)) and are now mandated by the standard:

1. **Schema-as-single-source-of-truth** — one schema row drives panel widget + slash + defaults reset. (`architecture-§5`, MUST)
2. **Modular `core/ modules/ defaults/ settings/ locales/` layout** — the canonical reference structure, used by every addon. (`layout-§1`)
3. **Chat-formatter via `_G[GLOBALSTRING]` override** instead of hooking chat events — architecturally taint-free. (`events-frames-taint-§5`, SHOULD)
4. **Combat-lockdown discipline** — secure frame writes defer on `PLAYER_REGEN_ENABLED`, but the options-panel open **refuses** under lockdown (gray notice, no defer-replay). (`events-frames-taint-§2`, `options-ui-§2`)
5. **Macro firewall** — a single module is the sole caller of protected `CreateMacro`/`EditMacro` APIs. (`events-frames-taint-§4`, MUST for any addon touching protected APIs)
6. **Measurable performance** — a vendored Ka0s-owned harness (`/<slash> perf`) whose two combat-gated arms differ only by whether the addon's code runs, because WoW's own profiler bills a shared frame's cost to whichever addon created it and so cannot answer *"is this cost even ours?"*. (`performance`, MUST for the wiring / SHOULD for coverage). The wiring MUST has exactly **one** exit, and it is evidenced and recorded rather than local: an addon that runs **no code while the player is in combat** may claim the **no-combat-path exemption** (`performance-§12`) — proven by a committed whole-repo `RegisterEvent` / `SetScript("OnUpdate"` / `C_Timer` sweep, claimed **once** as a row in the addon's deviation register with a re-check trigger, never re-argued per audit. It suspends the instance and its setup file, the `perf` **registration**, `<Addon>PerfDB`, suspend/resume, `tests/perf.lua` and `perf-runs/README.md`; it does **not** suspend whole-folder vendoring of `libs/LibKa0s/`, `perf` staying a **reserved** verb, a one-screen `docs/performance.md`, or the `perf: skip` release-notes line. Alongside it, `lizard` answers *"where is this getting hard to change?"*, generated by exactly `lizard -l lua -x "./libs/*" -x "./tests/_kit/*" .` from the repo root, with a one-line disposition for everything that newly crossed a threshold. The checkpoint is **release, not commit**. (`performance-§10`) A complexity number in Lua is not read the way it is elsewhere — `lizard` counts every `and`/`or` short-circuit as a decision, so twelve `k = rec.k or D.k` defaulting lines are CCN 13 with no visible branching, and the fix is a data table plus one loop rather than restructured logic (`performance-§10`). Acting on a finding is itself constrained (`performance-§11`): four permitted refactor shapes, no behavior change, no per-call allocation, and no extraction whose only purpose is the number (anti-pattern #52). A disposition has a **shelf life** — accepted across three consecutive release runs means fixed or tracked with an ID, because a watch list where everything is accepted carries no signal (anti-pattern #53).

7. **A consolidated automated-test record** — Alongside it, the **automated-test record** consolidates all four out-of-game suites — `luacheck`, the headless harness, the offline perf scenarios and `lizard` — into one frozen bundle per run at `docs/automated-tests/<YYYYMMDD-HHMMSS>/`, produced by the **vendored** `tests/_kit/run-automated-tests.sh`. **Two checkpoints gate differently, on purpose: commits on `lint` + `tests`; the tag on all four plus zero functions above CCN 15** — the release gate runs *before* anything is edited, treats a `skip` as NOT EVALUATED rather than a pass, and is evaluated by the release command from the run's manifest, never by the runner (whose exit code is unchanged, because the same script is the commit gate). **`lint` and `tests` gate a run; `perf` and `complexity` only record** — a threshold that fails a run teaches the collection to reach for `--no-verify` — and a missing tool is a **skip with its reason**, never a pass. `docs/automated-tests/RESULTS.md` is one file overwritten in place, one row per run across all four suites plus the current watch list, so its single-path git history is the trend line. A full bundle is produced at **every release**, before the tag, and never gates a commit. (`automated-tests`)

## The doc set

Fixed and predictable in every repo, so any human or agent lands in the same place:

- **Repo root** ships exactly **three** docs plus `LICENSE`, and never a fourth: a **full** `README.md` (player-facing), a **stub** `CLAUDE.md` (identity + "Standards compliance (read first)" + pointers into `docs/`), and **`DEPENDENCIES.md`** — the toolchain contract: every dependency named with the evidence for it, split **runtime / development / release-and-assets**, with copy-pasteable WSL2 / Ubuntu install commands that actually work (Ubuntu 24.04 marks Python `EXTERNALLY-MANAGED`, so `pipx`, not `pip`) plus a one-line verification per tool. A root **`CHANGELOG.md` is forbidden in an addon** — the player-facing history lives in the README's `## What's new` and `## Version History` — and **required in a Ka0s-owned library repo**, where `testing-§10`'s versioning suite reads it. (`documentation-§1`, `documentation-§2`, `documentation-§7`, `library-stack-§7`)
- **`docs/` canonical trio**, universal across the collection: `ARCHITECTURE.md` (engineer context), `testing.md` (how to verify), `smoke-tests.md` (the in-game suite). (`documentation-§3`)
- **`ARCHITECTURE.md` has nine mandated sections**, named because a bare count goes stale: Overview, Module Map, Settings Schema, Message Bus, Slash Commands, Event Subscriptions, Taint Notes, Known Limitations, and **`## Documented deviations`** — the **single home** for a ratified deviation, rows shaped `| Rule | What differs | Why | Decided | Re-check trigger |` with Rule a `filename-§N` reference and Re-check trigger the condition that ends the deviation. The reasoning may live in `docs/pending/LEDGER.md` or an audit bundle and the row cites it, but **a deviation not in the register is not ratified**. An audit reads the register **first** and records a matching entry as accepted with its id rather than re-filing it, and reports any entry whose cited rule the standard has since changed — so the register can neither be re-litigated nor quietly accumulate compliant behavior. (`documentation-§3`, `audit-review-history`)
- **Five required topic-detail docs**: `test-cases.md` (generated inventory), `performance.md`, `perf-runs/README.md` (in-game captures), `automated-tests/README.md`, `automated-tests/RESULTS.md` (generated). Four are unconditional; **`perf-runs/README.md` is required only while the perf harness is wired** — an addon holding the `performance-§12` exemption ships four, and `performance.md` stays required and shrinks to one screen. `complexity.md` was required through v2.18.0 and is **retired**. Any other topic-detail doc is optional and varies per addon. (`documentation-§3`)
- **No `TODO.md`** once released — GitHub issues are the single backlog (`documentation-§4`) — and **no `docs/agent-context.md`**: the scaffolding pack is fetched at runtime, never stored (`documentation-§3`, anti-patterns #49).

## How to use it

1. Read [`STANDARDS.md`](STANDARDS.md) and approve or request edits.
2. Scaffold a new addon with `/wow-addon:new-addon`, which **fetches** [`NEW_ADDON_CONTEXT.md`](NEW_ADDON_CONTEXT.md) to a temp directory and works from it — the pack is never written into the addon (`documentation-§3`, anti-patterns #49).
3. Audit existing addons against the standard periodically — run `/wow-addon:standards-audit` in each addon's repo; it writes a dated `docs/audits/<date>/` bundle there (see the [`../AUDIT.md`](../AUDIT.md) playbook).

## Scope boundaries

- **Retail (Mainline) only.** Classic/other flavors are out of scope; addons ship a single latest-Retail `## Interface:` line (`toc-file-§3`).
- **CI / GitHub Actions** are intentionally out of scope per Ka0s decision. **Local** testing and linting are **in scope** — a headless Lua 5.1 harness plus `luacheck` (`testing`).
- Shared Ka0s-owned code ships as the vendored **`LibKa0s`** library — five LibStub majors across eight files (Core, DebugLog, Slash, Options, Perf) plus a shared `testkit/` — not as a sibling addon, because library-stack-§6 forbids requiring another addon to be installed. Addons **consume** these rather than hand-rolling them (anti-patterns #47).
- **What earns promotion into `LibKa0s`** is a rule in its own right (`library-stack-§7`), because the opposite failure to #47 is harder to reverse: under the additive-only rule a wrong shared abstraction is surface the library keeps forever. Three bars — 2+ consumers with the same *semantics*, **no per-consumer escape hatches** (those flags are the consumers' divergence re-encoded as configuration), and a stable abstraction. Never promote on frequency alone: the collection's most-repeated shape sits at 400+ sites across nine repos and must stay inline (anti-pattern #55).

# Ka0s WoW Addon Standard (v2.19.0, 2026-08-04)

**Status:** Source of truth. All audit deviation reports and `NEW_ADDON_CONTEXT.md` template content derive from this standard. When the standard changes, bump the date and version at the top of this file.

**Adherence:** Every Ka0s addon **MUST** be built to this standard and **MUST** reference it: <https://github.com/tusharsaxena/WowAddonStandards> (see `documentation`, `toc-file-§1`).

**Audience:** future Ka0s and any agent (human or LLM) authoring or maintaining a Ka0s addon.

**Substrate:** Ace3. The ecosystem and Ka0s collection are aligned on it; deviations from Ace3 are case-by-case and must be justified.

**License:** MIT. Hostile licenses (`All Rights Reserved`) are forbidden.

## Reading this document

Each section uses these markers:

- **MUST** — non-negotiable; deviations are bugs.
- **SHOULD** — strongly preferred; deviations require a comment in code explaining why.
- **MAY** — optional; pick when it fits.
- **MUST NOT** / **SHOULD NOT** — forbidden patterns with cited reasons.

**Cross-references use the `filename-§N` scheme.** Every section lives in its own file under
`standards/standards/` and numbers its subsections **locally, from 1**. Reference a whole section by
its **bare filename** (e.g. `architecture`, `audit-review-history`); reference a subsection as
**`<filename>-§<n>`** (e.g. `architecture-§5`, `options-ui-§10`). This is the **only** cross-reference
form — the old global `§N.M` numbering is retired. When you add or reorder a section, update the
[Sections](#sections) list here.

**Reference implementations are described, not named.** This normative standard **MUST NOT** name a specific addon (from the Ka0s collection or the wider ecosystem) as a reference implementation. Instead it *describes* the implementation — what it does and how — in enough detail to be actionable on its own. This keeps the standard self-contained and durable when addons change or are renamed. The **named** research evidence behind these patterns (which real addons exhibit them) lives in the companion research document, `INDUSTRY_RESEARCH.md`, which is a standards-process input rather than part of the normative standard.

Where a Ka0s addon today already implements a rule well, it is called out as *"reference implementation (in the collection)"* with a description of the addon's role, never its name.

## Sections

The normative standard, in reading order. **All of these are part of the standard — read every one.**
Reference a whole section by its filename, a subsection as `filename-§N`.

- **[layout](standards/layout.md)** — the single modular `core/ defaults/ settings/ locales/ modules/` layout + load order; folder casing; typed `media/` subfolders.
- **[toc-file](standards/toc-file.md)** — required TOC fields + exact field order; single latest-Retail Interface; `#`-sectioned file listing.
- **[library-stack](standards/library-stack.md)** — mandatory/optional Ace3 libs; the Ka0s-owned `LibKa0s` umbrella vendored whole; vendor-and-commit over externals; no lib forks or suite dependencies.
- **[architecture](standards/architecture.md)** — namespace bootstrap; AceAddon; module pattern; closed message bus; schema-as-single-source.
- **[savedvariables](standards/savedvariables.md)** — AceDB structure; defaults; `schemaVersion` + migration runner.
- **[options-ui](standards/options-ui.md)** — the settings panel built by `LibKa0s-Options-1.0` from a descriptor: Blizzard Settings + raw AceGUI; eager category / lazy body; landing page, two-column flow, always-shown scrollbar.

- **[preview-mode](standards/preview-mode.md)** — placeholder-data preview/test mode for positionable displays.
- **[slash-commands](standards/slash-commands.md)** — AceConsole registration; schema-driven dispatch through `LibKa0s-Slash-1.0` over the addon's own `COMMANDS`; mandatory cyan chat tag; settings read/write output format.
- **[localization](standards/localization.md)** — metatable-fallback `NS.L`; English-string keys; locale-gated files; **match game data on stable IDs/tokens, never on localized display strings**; **US English as the source dialect for every authored string, comment, identifier, and doc**.
- **[events-frames-taint](standards/events-frames-taint.md)** — AceEvent; combat lockdown; taint-safe Blizzard replacement; frame pooling; combat "secret" values.
- **[public-api](standards/public-api.md)** — versioned `NS.API.v1` surface (only if the addon exposes one).
- **[compat](standards/compat.md)** — a single `Compat` module owning every deprecated / cross-patch API call.
- **[debug-logging](standards/debug-logging.md)** — the on-screen debug console from `LibKa0s-DebugLog-1.0` (styled like the main window), not the chat frame.
- **[packaging](standards/packaging.md)** — `.pkgmeta`: vendored libs, ignore lists, no `externals:`.
- **[lint](standards/lint.md)** — `.luacheckrc`: config and the zero-error gate.
- **[testing](standards/testing.md)** — headless Lua 5.1 test harness on the vendored `testkit` (`tests/_kit/`, never shipped); TDD; the green commit gate.
- **[performance](standards/performance.md)** — the vendored `LibKa0s-Perf-1.0` measurement harness; the gated bracket idiom; declared buckets; the `perf` verb; `<Addon>PerfDB`; the suspend/resume contract and the two-arm capture protocol; the offline scenario runner; the `lizard` complexity measurement and its release checkpoint.
- **[automated-tests](standards/automated-tests.md)** — the consolidated record of the four out-of-game suites: frozen `docs/automated-tests/<run>/` bundles, the vendored `tests/_kit/run-automated-tests.sh`, what gates (lint, tests) and what only records (perf, complexity), `RESULTS.md` as the single-path trend line, and the `ANALYSIS.md` write-up.
- **[documentation](standards/documentation.md)** — root README + stub `CLAUDE.md` + `DEPENDENCIES.md` (the WSL2/Ubuntu toolchain contract); the `docs/` trio (`ARCHITECTURE.md`, `testing.md`, `smoke-tests.md`); the three-place standards reference.
- **[audit-review-history](standards/audit-review-history.md)** — frozen dated `docs/audits/` + `docs/reviews/` bundles.
- **[versioning-git](standards/versioning-git.md)** — semver; trunk-based git workflow; commit only on green.
- **[naming-cheatsheet](standards/naming-cheatsheet.md)** — the naming conventions table.
- **[anti-patterns](standards/anti-patterns.md)** — the forbidden do-not list (#1–#51).
- **[open-evolutions](standards/open-evolutions.md)** — recorded directions for future versions.

## Changelog

- **v2.18.0 (2026-08-04):** **Two questions the standard could not previously answer — "what do I need installed?" and "is this getting harder to change?" — now have a fixed home, a fixed shape and a fixed moment.** **(1) A root `DEPENDENCIES.md` is now mandatory (documentation-§7, anti-pattern #50).** The toolchain was documented in four places that were each correct about their own slice and silent about the rest: `docs/testing.md`'s local-toolchain aside, a line in `CLAUDE.md`, the TOC's `## OptionalDeps`, and — for anything a *script* needed — nowhere. An audit of the collection found Python + Pillow driving asset regeneration in two addons, and in one a **vendored Real-ESRGAN binary linking a system Vulkan loader**, none of it named anywhere a new contributor would look. This failure is invisible to every gate the collection has, because on the maintainer's machine the software is already installed: the list is only ever wrong for the person who does not yet have it working, and that person cannot distinguish an incomplete list from their own mistake. So the rule demands what makes such a list survive: **evidence per entry** (file:line or the import that needs it), a **three-way split** — runtime/in-game, development, release-and-assets-only — so nobody installs a graphics stack to fix a typo, **WSL2/Ubuntu commands that actually work** (Ubuntu 24.04 marks Python `EXTERNALLY-MANAGED`, so the plausible-looking `pip install lizard` fails and `pipx` is the instruction), and a **one-line verification** per tool. It sits at root, not under `docs/`, because it is the one document needed on a machine where nothing runs yet. Root now ships exactly three docs plus `LICENSE` — and, per the v2.17.1 lesson, the count is never stated without naming all three. **(2) The complexity report is promoted from a loose SHOULD to a required doc with a release checkpoint (performance-§10, documentation-§3, anti-pattern #51).** It said "run `lizard` … excluding `libs/`" and left the invocation, the thresholds and the regeneration trigger open — and a report's value is almost entirely in the **diff between two releases**, which an unfixed invocation destroys: two reports produced by different commands are not comparable, so the trend line the report exists to draw never exists. Now fixed: the **exact command** (`lizard -l lua -x "./libs/*" -x "./tests/_kit/*" .` — excluding the vendored trees only, so the addon's own tests are measured), the **single path `docs/complexity.md` overwritten in place** so git history *is* the trend, a **generated-file header** and a **`## Watch list`** with a one-line disposition for everything that crossed a threshold since the previous report. The checkpoint is **release, not commit**: `MUST NOT gate commits` is retained verbatim and deliberately — a pre-commit complexity gate is the fastest way to teach a collection to reach for `--no-verify`, after which the gate protects nothing and the habit remains — while releases are already the moment the addon is looked at whole and are infrequent enough for the diff to carry signal. The staleness carve-out survives (absent `lizard` = stale, not non-compliant) but staleness must now be **visible**: leave the old report standing with its own date rather than deleting it or hand-editing its numbers, because a hand-edited complexity report is worse than an absent one — it reads as measured.

- **v2.17.1 (2026-08-03):** **Finishes the v2.17.0 rollout: the count is no longer four anywhere, and nothing still orders the forbidden file created.** v2.17.0 deleted `docs/agent-context.md` and every place that *enumerates* the canonical `docs/` set was updated correctly — but two classes of text were missed, and together they put the deleted file back into agents' heads. **(1) An unfilled fourth slot.** Three normative, non-changelog places still called the set a **quartet** while only ever naming three members: this file's own Sections map (which also still said "the four-place standards reference", already reduced to three by documentation-§6), `documentation-§3`'s "Beyond the quartet" — six lines below its own "canonical trio" — and `testing-§6`'s cross-reference. A model that reads "quartet", counts three names and supplies the fourth from pre-v2.17.0 memory produces exactly one answer, and it is `agent-context.md`; documentation-§6 already says why a rule that leaves a slot open is a rule that gets filled in wrong. All three now say **trio** and name `ARCHITECTURE.md`, `testing.md`, `smoke-tests.md` inline — the count is never stated without its members. **(2) Live imperatives that produce the file without naming it.** The pack's own first non-banner line still read "**Drop this file's *contents* into the new addon's `docs/` as the full agent context**" — directly contradicting the ⚠ CRITICAL banner twenty lines above it — and the same instruction survived in `NEW_ADDON.md`'s doc map and the root `README.md`'s "Start a new addon". "Drop the pack into `docs/` as the full agent context" **is** `docs/agent-context.md` in everything but name, so an agent following the imperative ships the forbidden file without ever reading the forbidden name. All are now fetch-and-discard wording, and the **"drop-in" label is retired** across `README.md`, `standards/README.md`, `EXECUTIVE_SUMMARY.md` and `CLAUDE.md` — it is the name that carried the retired behavior. Pack bumped to v2.17.1 alongside. **Patch bump: no rule changes.** Every normative requirement is what v2.17.0 made it; an addon compliant before this is compliant after. Drawn from a `/wow-addon:sync-docs` run that told a fully compliant addon its `docs/` was missing "the canonical trio's" `agent-context.md` — reconstructed from the open fourth slot, since no text in any repo asserts that membership.
- **v2.19.0 (2026-08-04):** **The four out-of-game suites now produce one consolidated, frozen record instead of four differently-shaped ones.** New section **[automated-tests](standards/automated-tests.md)**, placed after `performance`. Before this, `luacheck` and the harness left no record beyond a transient console, the offline perf runner wrote into a store shared with in-game captures, and `lizard` wrote a single hand-curated file — so *"what did this addon look like on the day 1.4.2 shipped"* took three archaeology passes and *"which of these moved between releases"* was unanswerable. **automated-tests-§1** — every run **MUST** be recorded under `docs/automated-tests/<YYYYMMDD-HHMMSS>/`, frozen once written, one file per suite plus a `manifest.json`; bundles are cumulative and **MUST NOT** be pruned. **§2** — the runner **MUST** be `tests/_kit/run-automated-tests.sh`, vendored whole-folder from `LibKa0s`'s `testkit/` so it is byte-identical everywhere under the existing vendoring gate, never re-implemented per addon; a CRLF-pinned repo shipping a `.sh` **MUST** carve it out with `*.sh text eol=lf`, or the script is broken on **every** checkout rather than one contributor's. **§3** — the load-bearing rule, and a deliberate refusal to do the obvious thing: `lint` and `tests` **gate**; `perf` and `complexity` are **recorded, never gating**. `performance-§9`/`§10` already said so for each tool alone, and consolidating them beside two real gates is exactly how that would have been reversed by accident — a threshold that fails a run teaches everyone to reach for `--no-verify`, after which the gate protects nothing and the habit remains. A missing tool **MUST** be recorded as a **skip with its reason**, never a pass: a green run that silently measured nothing is worse than a red one, because it is believed. **§4** — **`RESULTS.md`** is **one** file **overwritten in place**, one row per run across all four suites plus the current complexity watch list; the git history of that single path **is** the trend line, which is the same rule `performance-§10` applied to the complexity report and the reason the trend line did **not** move into the dated bundles. **§5** — a release run **MUST** carry an `ANALYSIS.md` written to the uniform prompt in the root `AUTOMATED_TESTS.md`, evidence-backed against the bundle it sits in. **§6** — a full bundle **MUST** be produced at **every release**, before the tag, and **MUST NOT** gate a commit; any subset **MAY** be run at any time. **§7** — **`docs/complexity.md` is retired** (its raw output is the bundle's `complexity.txt`, its trend line and watch list are `RESULTS.md`'s), and **`docs/perf-runs/` narrows to in-game captures only**, because a script cannot produce one: a directory written only by hand and a directory written only by a script are different things and are not merged. Ripples: `performance-§8`/`§9`/`§10` scoped rather than rewritten (every rule about the measurement itself is unchanged — only where the output lands moved), `documentation-§3`'s required topic-detail docs go from four to five (`complexity.md` out; `automated-tests/README.md` + `RESULTS.md` in), `testing-§4` names the runner's no-bundle pair as the commit gate and `testing-§7` records that the runner now keeps the perf output. Consumed by `LibKa0s` v1.6.0 (testkit revision 2).
- **v2.17.0 (2026-08-02):** **`docs/agent-context.md` is deleted from the standard, and shipping it is now an anti-pattern.** Since v1.1.0 the canonical `docs/` set has required a full agent brief built by "dropping in the contents of `NEW_ADDON_CONTEXT.md`" — the scaffolding pack. That was wrong in a way that only shows up after the addon exists. The pack is a **starter**: a kickstart walkthrough, a starter tree, ~250 lines of starter snippets and a *definition of done for v0.1.0*. Every question it answers is answered the moment the addon is scaffolded, so a copy left in the repo describes the addon **on the day it was born, forever** — and because it is the file a session loads as *working context*, a stale copy does not go quiet, it gets **followed**. The failure is silent and it compounds: a pack still showing how to hand-write a debug console, a slash dispatcher or a test harness will get one hand-written, in an addon that replaced all three with `LibKa0s` (anti-pattern #47), and nothing goes red — no test covers a doc and lint does not read prose. The evidence is the collection itself: eight repos seeded from one pack had drifted to **72, 87, 90, 148, 194, 248, 620 and 764 lines**, none wrong when written and none true now. **documentation-§3** drops the file, the canonical set goes **quartet → trio** (`ARCHITECTURE.md`, `testing.md`, `smoke-tests.md`), and a new **CRITICAL** subsection states the prohibition with the `curl` that replaces it: fetch the pack into a temp directory for the session that scaffolds, never write it into the addon. **documentation-§2** stops describing the root `CLAUDE.md` as a pointer to a brief — it **is** the brief now, and its pointer list **MUST NOT** name a file the standard forbids. **documentation-§6** goes **four places → three** (TOC `X-Standard`, README badge, `CLAUDE.md` "Standards compliance"), because a rule whose fourth home is a forbidden file is a rule that audits itself into a permanent failure; the note says so explicitly rather than leaving the missing item to be re-added by someone counting to four. New **anti-pattern #49** (shipping the pack); **#34** loses its `agent-context` half. `NEW_ADDON_CONTEXT.md` opens with a **⚠ CRITICAL — FETCH THIS, NEVER STORE IT** banner carrying the same `curl`, and its own item 20 / 20c / DoD checklist move with the rule. Rippled into `NEW_ADDON.md` (step 2 is now "read, do NOT copy in"), the pack itself (bumped to v2.17.0), `layout.md`, `naming-cheatsheet.md`, `EXECUTIVE_SUMMARY.md` and the Sections list (`#1–#48` → `#1–#49`). **Minor bump, and the rare kind an addon satisfies by DELETING something:** every addon carrying `docs/agent-context.md` is now non-compliant; the fix is to migrate anything genuinely addon-specific that accumulated in it into `docs/ARCHITECTURE.md` or the `CLAUDE.md` stub, then delete the file — the pack's own generic content is deleted outright, never migrated. Drawn from a Ka0s Panel Master LibKa0s adoption where the brief had to be hand-patched mid-session because four of its "patterns to reproduce" were teaching the next agent to rebuild exactly what the adoption had just deleted.
- **v2.16.0 (2026-08-02):** **The Ka0s window edge is now specified normatively, down to the values.** standalone-windows already made it a **MUST** to take a window's look from `LibKa0s-Core-1.0`'s shared `SKIN` and `ApplySkin` seam — but it never said what that look *is*, so the seam guaranteed only that windows sharing it matched each other. They did not. Five debug consoles side by side split into two groups: **BankLedger** and **LootHistory** drew a flat 1px **black** outer edge with a 1px light-grey highlight just inside it, a gold title and a grey divider, and passed the `applySkin` **function** hook (debug-logging) so their consoles kept matching their own main windows; **AbsorbTracker**, **ConsumableMaster** and **KickCD** passed nothing and got the library's 12px `UI-Tooltip-Border` with a black divider and an untinted title. Two of the five had overridden the shared seam to look right, which is the shared seam failing at the one thing it exists for. New **standalone-windows-§2 (The Ka0s window edge)** pins all five parts in a table — background, outer edge, inner highlight, title, divider — with their exact textures and colours, and states the rule the screenshots made obvious: the edge is **two lines, not one**, and a single-line border of either colour is the deviation that is hardest to see in isolation because it only reads as wrong beside a window that has both. A window **MUST NOT** hardcode any of the values; it assigns `frame.title` / `frame.divider` and lets `ApplySkin` tint them, so the **same** treatment covers the main window, the debug console, the console's copy window and the perf panel. The `applySkin` hook survives, with its purpose narrowed: chrome differing in **shape**, not a restatement of these colours — restating them is a fork of a shared constant by another name (anti-patterns #47) and an audit **SHOULD** flag it. The section also fixes the ownership the old wording left ambiguous: changing any of these values is a **standard** change that lands here first and in `Core.SKIN` second, because it alters every Ka0s window at once. A second bullet draws the line the same screenshot pass exposed one field along: **the edge is shared; the close control is not.** A host **MAY** draw its own × on **its own** windows — a large data browser reasonably closes with a more visible glyph than a small diagnostic window — but a window a **library** draws (the debug console, its copy window, the perf panel) **MUST** keep the library's, and a host **MUST NOT** push its own onto them through a module's `makeCloseButton` hook. Those windows are the surface a user compares across addons; the host's main window is not. The same two adopters had taken that hook for the same reason, so their diagnostic windows closed with a 24Ý24 class-coloured × where the other three had Core's thin 18Ý18. `debug-logging`'s guarantee paragraph now carries the MUST NOT, and **LibKa0s v1.3.1** (DebugLog minor 6) documents the field as rarely-right and currently unused, with a regression guard that a console built without it reaches `Core.MakeCloseButton` once per window. `debug-logging`'s "what the library guarantees" paragraph now names the treatment rather than only pointing at `SKIN`. Carried by **LibKa0s v1.3.0** (**Core minor 3**, **DebugLog minor 5**): `Core.SKIN` changes values, `Core.ApplySkin` grows the three calls a table can never describe (the inner-border child frame, built once; the title tint; the divider tint) and takes an optional `skin` argument so DebugLog's `skin` override reaches one implementation, and DebugLog's `defaultApplySkin` becomes a delegate to it while its divider stops being hardcoded black — a literal that was invisible only while the default border was also black. **Minor bump, and the rare kind that is a MUST an addon satisfies by doing nothing:** re-vendor the folder and the three addons on the old default change appearance; the two already drawing this edge do not move a pixel. What becomes non-compliant is *hardcoding* the values or overriding the seam to restate them. Rippled into `NEW_ADDON_CONTEXT.md` (item 24; pack bumped to v2.16.0) and `EXECUTIVE_SUMMARY.md` (current-version pointer). Drawn from a Ka0s Loot History LibKa0s adoption whose in-game smoke pass put all five consoles on screen at once — the inconsistency was invisible in every repo's own screenshots and obvious the moment they were side by side.
- **v2.15.0 (2026-07-31):** **Six sections flip from describing how to build a subsystem to mandating that you consume the Ka0s-owned library that already is one.** v2.12.0 introduced `LibKa0s` with a single module (`LibKa0s-Perf-1.0`) and wrote **performance** in the consume-a-library register. That extraction has now been completed and verified in-game: **five** LibStub majors across eight files ship in the `LibKa0s` repo's `LibKa0s/` folder — **`LibKa0s-Core-1.0`** (secret-safe stringification, the window skin and close button, the prefixed chat printer), **`LibKa0s-DebugLog-1.0`** (the on-screen console, both formatters, the 500-line buffer, the enable seam), **`LibKa0s-Slash-1.0`** (the dispatcher, help renderer, schema CLI and type-aware value parser), **`LibKa0s-Options-1.0`** (the Blizzard settings-canvas shell, the widget makers, the two-column flow engine, the always-shown scrollbar patch) and **`LibKa0s-Perf-1.0`** (the A/B capture) — plus a shared headless **`testkit`** vendored into each consumer's `tests/_kit/`. **debug-logging**, **options-ui**, **slash-commands**, **testing**, **library-stack** and **performance** are rewritten accordingly: what an addon writes is a **descriptor** and a **degradation stub** in its own setup file (`core/CoreSetup.lua`, `core/DebugLogSetup.lua`, `settings/OptionsSetup.lua`, the slash descriptor, `core/PerfSetup.lua`), and the implementation detail those sections used to specify is demoted to rationale — kept, because a rule without its reason is deleted by the next author who finds it inconvenient. The degradation contract is uniform and load-bearing: DebugLog, Slash, Options and Perf each `return` **before** `LibStub:NewLibrary` when Core is absent or older than their floor, so a module is **absent** rather than half-wired and the host's stub is what actually runs. Two new anti-patterns: **#47** hand-rolling (or forking) a console, options toolkit, slash dispatcher or test harness a LibKa0s module already provides — the drift failure the extraction exists to end, and the one nothing goes red for; **#48** partial or per-module re-vendoring of a multi-file major, whose two failure modes are a module going silently **absent** (no Core) and an instance that `:New`s successfully and then fails at **call** time (shell without its attach file). The Sections list's `anti-patterns` range goes `#1–#46` → `#1–#48` and six section blurbs are rewritten. Both playbooks move with it: **`AUDIT.md`** now treats consuming the library as the **compliant** state and hand-rolling as the deviation, puts the `diff -r` vendor-sync check in the evidence set for the whole `LibKa0s/` folder, and has the auditor check the setup file's stub against every member the addon actually calls — while knowing that the Options stub is deliberately **load-completing** rather than member-answering and is not an inconsistency; **`NEW_ADDON.md`** scaffolds a new addon vendoring the whole `LibKa0s/` folder plus `testkit/` → `tests/_kit/`, TOC-listing `libs\LibKa0s\LibKa0s.xml` after Ace3, and born with the setup files rather than hand-built equivalents. **Minor bump:** an addon carrying its own console, options toolkit, dispatcher or harness is now non-compliant and surfaces it on its next `standards-audit`. Per-repo work — vendor the folder, write five descriptors, write the stubs, delete the replaced files — but **additive to the standard's rules**: nothing that was correct becomes wrong, the required behavior is unchanged, and it is the same behavior, now written once. Drawn from a Ka0s Absorb Tracker pass that extracted all five modules and re-adopted them as consumer #1, verified by a full in-game smoke pass.
- **v2.14.0 (2026-07-30):** **The README is now explicitly written for two renderers, and angle-bracket placeholders are forbidden in it.** v2.13.1 fixed one CurseForge rendering divergence (the badge's `%20`); this generalizes the finding, because the same class of bug was sitting in seven of the eight roster READMEs. **documentation-§1** gains a normative paragraph ahead of the canonical-structure list: the README renders on **GitHub**, where it is written and reviewed, and on **CurseForge**, where players actually read it — and CurseForge is stricter about HTML and looser about escapes. Two MUST NOTs follow, both chosen because they fail **silently on the surface a maintainer never checks**: (1) **angle-bracket placeholders MUST NOT appear in shipped README content** — CurseForge strips `<setting>`, `<name>`, `<value>` as unknown HTML tags **even inside backticks**, so `` `/bl set <setting> <value>` `` reaches players as `/bl set` with both placeholders silently deleted while rendering perfectly on GitHub; write the argument bare and keep `[…]` for genuinely optional arguments, which survives both; (2) **percent-escapes MUST NOT be used for spaces in badge URLs** (the v2.13.1 correction, now stated as a general rule rather than a note on one template). - **v2.12.0 (2026-07-30):** **Performance measurement becomes part of the standard, carried by a Ka0s-owned vendored library rather than per-addon code.** New section **[performance](standards/performance.md)** (added to the Sections list, after `testing`) makes ten things normative. The premise is that WoW's built-in Addon Profiler **cannot** answer *"is this cost even ours?"* — it bills a **shared** library's dispatch frame to whichever addon **created** it, so enabling and disabling addons moves the blame around and the first-alphabetical Ace addon absorbs its siblings' cost — so the only trustworthy answer is an A/B on the **same fight** with load order and shared-frame ownership held fixed. **performance-§1** — every addon **MUST** vendor **`LibKa0s-Perf-1.0`** under `libs/LibKa0s/`, create **one instance per addon at load** from a descriptor in `core/PerfSetup.lua` (`NS.Perf = LibStub("LibKa0s-Perf-1.0"):New(descriptor)`), positioned in the TOC **before** any module taking `NS.Perf` as a load-time upvalue, and degrade to a stub carrying every member the addon actually calls when the lib is absent; **MUST NOT** hand-roll a private probe, and **MUST NOT** let the lib share a frame between hosts. **performance-§2** — the gated bracket idiom `local t0 = Perf.on and debugprofilestop()` … `if t0 then Perf.Note(key, debugprofilestop() - t0) end` is pinned as the **only** form: one upvalue read, one field read, one boolean test when capture is off, with a hard **MUST NOT** on allocating/calling/formatting inside a dormant bracket, and the offline zero-overhead scenario as **required evidence** rather than a comment claiming it. **performance-§3** — buckets are **declared** in the descriptor in report order, nesting is declared with `within` rather than explained in prose, nested totals **MUST NOT** be summed, and a declared bucket no bracket reaches is *"a lie in every report"* that the addon's own suite MUST pin. **performance-§4** — **`perf` is a reserved slash verb** (slash-commands-§2) dispatched through the addon's own `NS.COMMANDS` (slash-commands-§3) and **never registered by the library**, which returns lines the host prints; a bare `/<slash> perf` **MUST** be the entry point to a run and **SHOULD** open a guided step panel offering only the next legal step, because ordering silently ruins captures and a numbered chat list scrolls away the moment combat starts. **performance-§5** — **`<Addon>PerfDB`**, a bounded capture ring, **MUST** live outside the AceDB tree so it never rides profile copy/reset/switch. **performance-§6** — the **suspend/resume host contract**: inert **without a `/reload`** (reloading shifts frame ownership, the confound itself), visibility enforced **at the source** in the show-decision ladder rather than by hiding frames (hidden frames come back and the suspended arm then measures the addon still working), restore from **current** state, never persist the flag, and **resume before saving or reporting** so a persistence error cannot strand the addon inert. **performance-§7** — the **capture protocol**: clean arm first, suspend as the finer second arm, windows opened on the player's combat **state** rather than the combat *events* (suspend unregisters the event frames, so the suspended arm would never see `PLAYER_REGEN_DISABLED`), no comparing arms across different addon sets or a `/reload`, and the **buckets** read as the addon's cost with the frame-time delta treated as unresolved below the harness's measured spread. **performance-§8** — record schema and the standing, cumulative **`docs/perf-runs/`** store, where a committed capture is evidence that outlives the write-up interpreting it. **performance-§9** — **`tests/perf.lua`**, the offline scenario runner: outside the green gate, asserting **only** deterministic quantities (API calls, bytes allocated), with a hard **MUST NOT** on wall-clock assertions. **performance-§10** — `lizard` complexity as a committed **report-only** `docs/complexity.md`, explicitly **not** gating. Adoption strength is **MUST for the wiring, SHOULD for coverage** — which paths get buckets is addon-specific, but uniform wiring is what makes *"run `/<slash> perf` and send me the JSON"* true of any Ka0s addon. **Cross-section ripples:** new **library-stack-§7 (Ka0s-owned shared libs)** — the `LibKa0s` umbrella vendored exactly as Ace3 is, **one LibStub major per module**, additive-only contracts, plus the two rules that only bite when the library's author and its consumers are the same person: a **vendor-sync MUST** (the vendored copy byte-identical to the source repo's ship folder, `diff -r` empty, a **re-vendor commit in every consumer** per library change, ideally its own commit) and a **module-versioning MUST** (a LibStub **minor per file** bumped on every released change, never in lockstep, files paired by version not merely by presence, a published registry of live per-file minors, the lib repo's semver kept as a separate axis, and the bump↔changelog coupling made mechanical).

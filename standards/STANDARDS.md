# Ka0s WoW Addon Standard (v2.52.0, 2026-09-16)

**Status:** Source of truth. All audit deviation reports and `NEW_ADDON_CONTEXT.md` template content derive from this standard. When the standard changes, bump the date and version at the top of this file.

**Adherence:** Every Ka0s addon **MUST** be built to this standard and **MUST** reference it: <https://github.com/tusharsaxena/WowAddonStandards> (see `documentation`, `toc-file-§1`).

**Audience:** future Ka0s and any agent (human or LLM) authoring or maintaining a Ka0s addon.

**Substrate:** Ace3. The ecosystem and Ka0s collection are aligned on it; deviations from Ace3 are case-by-case and must be justified.

**License:** MIT. Hostile licenses (`All Rights Reserved`) are forbidden.

## Reading this document

Each section uses these markers:

- **MUST** — non-negotiable; deviations are bugs.
- **SHOULD** — strongly preferred; deviations require a comment in code explaining why.
- **MAY** — optional; pick when it fits.
- **MUST NOT** / **SHOULD NOT** — forbidden patterns with cited reasons.

**Cross-references use the `filename-§N` scheme.** Every section lives in its own file under
`standards/standards/` and numbers its subsections **locally, from 1**. Reference a whole section by
its **bare filename** (e.g. `architecture`, `audit-review-history`); reference a subsection as
**`<filename>-§<n>`** (e.g. `architecture-§5`, `options-ui-§10`). This is the **only** cross-reference
form — the old global `§N.M` numbering is retired. When you add or reorder a section, update the
[Sections](#sections) list here.

**Reference implementations are described, not named.** This normative standard **MUST NOT** name a specific addon (from the Ka0s collection or the wider ecosystem) as a reference implementation. Instead it *describes* the implementation — what it does and how — in enough detail to be actionable on its own. This keeps the standard self-contained and durable when addons change or are renamed. The **named** research evidence behind these patterns (which real addons exhibit them) lives in the companion research document, `INDUSTRY_RESEARCH.md`, which is a standards-process input rather than part of the normative standard.

Where a Ka0s addon today already implements a rule well, it is called out as *"reference implementation (in the collection)"* with a description of the addon's role, never its name.

## Sections

The normative standard, in reading order. **All of these are part of the standard — read every one.**
Reference a whole section by its filename, a subsection as `filename-§N`.

- **[layout](standards/layout.md)** — the single modular `core/ defaults/ settings/ locales/ modules/` layout; the folder load order `libs/ → locales/ → core/ → defaults/ → modules/ → settings/`, and dependency-correct order **inside** `core/` in place of a fixed file prefix; folder casing; typed `media/` subfolders, holding only what the shared media library does not already ship; **the two required logo files** — the 128×128 uncompressed 32-bit `<addon>.logo.128.tga` the TOC, the minimap button and the broker object share, and the larger landing-page asset beside it — with the exact TGA type, the power-of-two reason and the Pillow recipe that regenerates the small one; and **what the 1500-line cap binds** — every authored `.lua` the repository tracks, `tests/` included and a library repo's own payload included, with vendored code and generated non-shipping data the only two carve-outs, plus the three terminal states an over-cap file may sit in.
- **[toc-file](standards/toc-file.md)** — required TOC fields + exact field order, including what an **unpublished** addon does about `X-Curse-Project-ID` and the now-**mandatory** `## IconTexture`, which points at the addon's **own logo** and never at a Blizzard icon path or a numeric file id; single latest-Retail Interface; `#`-sectioned file listing, and the **load-bearing / conventional** annotation — a MUST at every load-bearing position, measured against that denominator and not against the line count, and a per-group SHOULD everywhere else.
- **[library-stack](standards/library-stack.md)** — the Ace3 substrate, mandatory **when used** and governed by §3's prune rule rather than read as a floor every addon carries, and the three ways a vendored lib is *reached*; **LibDataBroker-1.1 and LibDBIcon-1.0 vendored always**, since every addon ships a launcher; the Ka0s-owned `LibKa0s` umbrella — ten majors across fourteen files — vendored whole; vendor-and-commit over externals; the vendor-sync MUST and the provenance line in root `CLAUDE.md` that names the tag both payloads are gated against; **the shared media library** — the icon catalog, monospace face and bar textures every addon already ships, the folder-name argument every path takes, and the rule that a missing mark is added upstream rather than drawn locally; no lib forks or suite dependencies; what earns promotion into a shared lib — the three bars (2+ consumers with the same *semantics*, no per-consumer escape hatches, a stable abstraction), and why high frequency alone is a reason to stay inline; and **what binds a Ka0s-owned library repo itself** — the **three applicability lists** (applies unchanged, applies read for a library, does not apply), exhaustive over the Sections list and defaulting to *applies*, with the substitutes list beside them answering a different question and not one of the three; and the rule that a re-registration against AceGUI's **process-global widget registry** is the library's to make, never an addon's.
- **[architecture](standards/architecture.md)** — namespace bootstrap; AceAddon; module pattern; the closed message bus and the shape of addon it binds (two or more feature modules, or any module registering game events); schema-as-single-source — one helper for every write to a schema-row path, and for a **structural registry** no row can address (a collection the player creates and deletes members of), one registry writer named in `ARCHITECTURE.md`, with the load pass that seeds and repairs it named beside it; and **named non-setting state** — geometry only a drag or a resize determines, a remembered view, learned or recorded data, a vendored library's own writes — which is written outside the helper by writers `ARCHITECTURE.md` lists under one named owner module, with no register row.
- **[savedvariables](standards/savedvariables.md)** — AceDB structure; defaults; `schemaVersion` + migration runner; the diagnostics global carve-out; `== nil` rather than `or` when defaulting a stored value whose falsy state is a user choice.
- **[options-ui](standards/options-ui.md)** — the settings panel built by `LibKa0s-Options-1.0` from a descriptor: Blizzard Settings + raw AceGUI; eager category / lazy body; landing page, two-column flow, always-shown scrollbar; the **global reset** — one act (a reset of the active profile, never a second walk of the schema), one verbatim warning, one blast radius; and the panel's **content**, not only its shell: **every page draws a tab strip** — one tab per section, including a one-section page, wrapping rather than truncating, with a geometry that does not move when the selection does and a session-only active tab, the AceConfig-rendered Profiles page the single exemption — under the **chrome block above the strip**, which carries the page's picker and is never boxed a second time — **one row**, holding the identity controls, with a page's remaining page-wide acts moving to a `General` FIRST tab where they will not fit beside them; a **`Master controls`** first tab on the General page with a canonical row set in every addon — including the unconditional **Minimap button** row, which takes the **first** column precisely because every addon has one while only some have a *Test mode* to pair beside it; the canonical **font, border and bar control groups** and their exact row orders; **subsection headings** wherever a tab mixes control types; the **class-color companion** beside every color control, resolving to the tracked unit's class where the control is unit-scoped and the player's everywhere else; and the shared **reorder list**, whose handle and bounded row box are the library's while the row's contents stay the consumer's; plus the **hollow composer** — where the library is absent the stub answers an empty row list, which is the compliant answer and not a licence to hand-write the block back — and the addon-wide **broadcast meta row** as the one named exemption from the composer MUST, bounded by five conditions.
- **[standalone-windows](standards/standalone-windows.md)** — non-secure main windows / data browsers (no combat gate; `UISpecialFrames`; pooled rows; the normative Ka0s window edge; title-bar controls and close buttons drawn from the shared icon catalog, and the labels a mark must not replace; **the one close-button wrapper every window's close control is built through**, the grep that proves no call site bypassed it, and the four conditions under which a **reasoned decline** of that wrapper is a terminal compliant state whose only possible finding is a missing register row).
- **[preview-mode](standards/preview-mode.md)** — placeholder-data preview/test mode for positionable displays.
- **[launcher](standards/launcher.md)** — the minimap button and the broker plugin every addon ships, and the fact that they are **one LibDataBroker-1.1 object registered twice** rather than two features: LibDBIcon-1.0 draws the button from it and any broker display draws its row from the same object, so one `OnClick` serves both. **Left-click is a three-rung rule, first match wins** — a primary window, else a preview switch (test mode, or lock/unlock where unlocking is the preview), else the settings panel — with each rostered addon's rung recorded in `ADDONS.md`; **right-click always opens the settings panel**. Visibility is one Master-controls row stored at **LibDBIcon's own `minimap.hide`**, never a second key; the broker object has **no** enable setting, by design. The icon is the addon's own logo, the same file the TOC names.
- **[slash-commands](standards/slash-commands.md)** — AceConsole registration; schema-driven dispatch through `LibKa0s-Slash-1.0` over the addon's own `COMMANDS`; the **reserved verb list**, which now includes `enable` / `disable` as **aliases** onto the Master-controls *Enable* row's stored path through the same write seam, holding no state of their own; mandatory cyan chat tag; settings read/write output format.
- **[localization](standards/localization.md)** — metatable-fallback `NS.L`; English-string keys; locale-gated files; **match game data on stable IDs/tokens, never on localized display strings**; **US English as the source dialect for every authored string, comment, identifier, and doc**; and the two terminal states of the routing SHOULD — strings routed, or an English-only decision recorded as a deviation row; and the **canonical British-spelling list**, published here once so that every mechanical gate copies it whole instead of inventing a private subset.
- **[events-frames-taint](standards/events-frames-taint.md)** — AceEvent; combat lockdown; taint-safe Blizzard replacement; frame pooling; combat "secret" values.
- **[public-api](standards/public-api.md)** — versioned `NS.API.v1` surface (only if the addon exposes one).
- **[compat](standards/compat.md)** — a single `Compat` module owning every deprecated / cross-patch API call.
- **[debug-logging](standards/debug-logging.md)** — the on-screen debug console from `LibKa0s-DebugLog-1.0` (styled like the main window), not the chat frame.
- **[packaging](standards/packaging.md)** — `.pkgmeta`: vendored libs, ignore lists that account for every root dot-entry including `.pkgmeta` itself, no `externals:`.
- **[line-endings](standards/line-endings.md)** — `.gitattributes` is mandatory in **every** repo, and the absent file is the defect: two pins, one per repo kind — `* text=auto eol=crlf` where the repo ships Lua to the client (the addons + a library vendored into their `libs/`), `* text=auto eol=lf` where it ships nothing to the client (the standards and plugin repos) — plus `*.sh text eol=lf` in **both**, binaries marked `binary`, one canonical file body per kind to diff against, the **§5 appendix** — the only thing that may sit below that body, carrying a path-keyed `binary` mark for a file no extension rule can reach — the vendored EOL gate `§7` now names rather than only supplying a command for, and the remediation rule that `git add --renormalize .` fixes the **index** and not the working tree.
- **[lint](standards/lint.md)** — `.luacheckrc`: config and the zero-error gate, with **the test tree in scope** — only `tests/_kit/` is excluded, being a vendored copy linted in its own repo, and the harness global is declared in a `files["tests/"]` stanza rather than in top-level `read_globals`.
- **[testing](standards/testing.md)** — headless Lua 5.1 test harness on the vendored `testkit` (`tests/_kit/`, never shipped); TDD; the green commit gate; the three pinned load lists (TOC files, vendored library files, the suite list); the stub-surface parity case; the two vendored-payload gates — library-side kit-sync and consumer-side — and the skip as a third case status; characterization tests before a behavior-preserving refactor; and the green gate's **speed** as a governed property — measure before optimizing, never re-parse source already read, never spawn one process per item, and parallelism last and opt-in.
- **[performance](standards/performance.md)** — the vendored `LibKa0s-Perf-1.0` measurement harness; the two sanctioned bracket shapes and how the region's exits decide between them; declared buckets and observed containment; the `perf` verb; `<Addon>PerfDB`; the suspend/resume contract and the two-arm capture protocol; the **perf analysis bundle** — one frozen `docs/perf-analysis/<YYYYMMDD-HHMMSS>/` per in-game capture, carrying the report, the verbatim record and the `ANALYSIS.md` reading of it together, stamped from the record's own timestamp; the offline scenario runner; the `lizard` complexity measurement and its release checkpoint; how to read a Lua complexity number (`and`/`or` count as decisions) and the permitted shapes for acting on one; and the **no-combat-path exemption** from the wiring MUST.
- **[automated-tests](standards/automated-tests.md)** — the consolidated record of the four out-of-game suites: frozen `docs/automated-tests/<run>/` bundles, the vendored `tests/_kit/run-automated-tests.sh`, what gates (lint, tests) and what only records (perf, complexity), `RESULTS.md` as the single-path trend line, the `ANALYSIS.md` write-up, the **one boundary** between what is generated and what is authored — everything in `RESULTS.md` is the runner's output and the complexity watch list's `Disposition` is the one authored cell in the file — and the **release gate**: all four suites plus zero CCN > 15 at the tag, which the commit gate deliberately is not.
- **[documentation](standards/documentation.md)** — root README + stub `CLAUDE.md` + `DEPENDENCIES.md` (the WSL2/Ubuntu toolchain contract), and no `CHANGELOG.md` at an addon root; the `docs/` trio (`ARCHITECTURE.md`, `testing.md`, `smoke-tests.md`); the **three-tier topic-detail model** — Tier 1 required and unconditional (`scope.md`, `module-map.md`, `schema.md`, `settings-panel.md`, `data-flow.md`, `common-tasks.md`), Tier 2 required per stated trigger under canonical names, Tier 3 addon-specific and free-form — with every Tier 2 trigger stated as a count, `compat-layer.md`'s included — and with `ARCHITECTURE.md` as a capped hub carrying `## Documentation map` and `## Documented deviations`, the latter the single home of a ratified deviation and the former **four** tables rather than three, its fourth being `### Verification and record` for the seven documents that belong to no tier; the player-facing README's canonical section order, its unlinked standard badge and its **MUST NOT** on a bundled-library inventory; the LibKa0s provenance line in root `CLAUDE.md`; the three-place standards reference, and how the standard itself is cited; and **what binds a documentation-and-tooling repo** (§8) — the third repo kind, neither addon nor library, with its own three applicability lists exhaustive over the Sections list, a five-section `ARCHITECTURE.md` in place of the ten, an honest near-empty `DEPENDENCIES.md`, and the stated trigger that re-reads `lint`/`testing`/`automated-tests` the day such a repo tracks its first `.lua`.
- **[audit-review-history](standards/audit-review-history.md)** — frozen dated `docs/audits/` + `docs/reviews/` bundles; the **three MUSTs on the deviation register** — read it before filing, report an entry whose cited rule the standard has since changed, and evaluate every row's re-check trigger against the tree while resolving every evidence id it cites; and the issue-audit decision store, which is **GitHub issues on the addon's own repo** carrying status and severity as two **labels** — `state:done`/`state:will-not-do` (closed), `state:triaged`/`state:untriaged` (open), plus `severity:critical`…`severity:low` — with the title carrying neither, the `gh` CLI subcommands as the only sanctioned surface, and `docs/pending/LEDGER.md` retired.
- **[versioning-git](standards/versioning-git.md)** — semver; trunk-based git workflow; commit only on green.
- **[naming-cheatsheet](standards/naming-cheatsheet.md)** — the naming conventions table.
- **[anti-patterns](standards/anti-patterns.md)** — the forbidden do-not list (#1–#82).
- **[open-evolutions](standards/open-evolutions.md)** — recorded directions for future versions.

## Changelog

- **v2.52.0 (2026-09-16):** **Every addon gets a launcher, an `enable` / `disable` pair, and its own face — and the launcher is one object, not two features.** Four decisions of the collection owner's land together because they are one surface. **(1) `slash-commands-§2` reserves `enable` and `disable`.** The addon-wide switch has been the first row of `options-ui-§15`'s Master controls set since the set was canonical; what was missing was the CLI route to it, so the answer to *turn this off without opening anything* was *find the panel first*. The two verbs are **aliases**: they write the **same stored path** through the **same single write seam** the checkbox writes through, hold **no state of their own**, and are **MUST NOT** re-used for enabling a module, a feature or a unit — `/<slash> disable` meaning *the addon* here and *one feature* there is the collision the reserved list exists to prevent. **(2) A new section, `launcher`, and it exists because nothing owned the subject.** Every addon **MUST** ship a minimap button via LibDBIcon-1.0 **and** a broker plugin, and they are **one LibDataBroker-1.1 object registered twice** — one `OnClick`, one icon, one name (the addon's folder name, since LibDBIcon keys its saved table by it and a display labels the plugin with it). Written as two features it would be implemented as two in eleven repos and drift on the first behavior change, which is why the section leads on the object rather than on the button. **Left-click is a three-rung rule, first match wins:** a **primary window** → toggle it (Bank Ledger's ledger browser, Loot History's browser, Multi Meters' windows, WhatGroup's group popup); else a **preview switch** → toggle it, the test mode where there is one (Absorb Tracker, Party Frame Enhanced) or lock/unlock where unlocking *is* the preview under `options-ui-§15`'s exemption (Aura Master, Consumable Master's macro bar, KickCD, Panel Master); else the **settings panel** (Pretty Chat alone). **Right-click always opens the settings panel**, on every addon — which is what lets rungs (a) and (b) spend the left button on something better. The rung is not a preference and there is no setting that reassigns either button; each rostered addon's rung is a **column on `ADDONS.md`**, so an audit reads it instead of re-deriving it from the addon's shape and guessing. **(3) The broker object has no enable setting, deliberately.** A broker display shows what it chooses to show and already offers a per-plugin toggle of its own; an addon that hides itself from one is solving the display's problem in the wrong repo, in a row the player has to find first. **(4) `toc-file-§1`'s `## IconTexture` stops being *optional but encouraged*** and **MUST** name the addon's own logo — never a Blizzard icon path, never a numeric file id — because the same file is also the button's icon and the broker object's icon, so the AddOns list, the minimap and a broker display show one identity rather than three. **The tell for the format was a single proven file.** One logo in the collection is proven to render as an `IconTexture` in-game and it is TGA **image type 2, 32 bpp**; the **RLE (type 10)** logos the collection also ships are unproven in that role, and an icon that fails to load draws **nothing** and raises **nothing**, so no gate would ever report it. `layout-§4` — appended, because `layout-§3` owns shipped media — therefore fixes the file at **`media/logos/<addon>.logo.128.tga`**, 128×128 (power-of-two, which the existing 300×300 logos are not), uncompressed 32-bit, ~64 KB, generated from the 2000×2000 `.png` source already beside it by a stated recipe (`Image.open(src).convert("RGBA").resize((128, 128), Image.LANCZOS).save(out, format="TGA")`) so it is reproducible rather than an export whose settings somebody has to remember. The settings panel's landing-page logo is a **different, larger file** and is untouched (`options-ui-§5`). **The Master-controls row, and why its column is not arbitrary.** `options-ui-§15`'s canonical set gains an unconditional **`Minimap button`** row in the **first** column of the line that already held *Test mode*, which moves to the **second**. The asymmetry is the reason and the section says so: every addon has a minimap button, only some have a test mode, so the always-present row in column 1 leaves an addon without a test mode a tidy single row instead of a hole in the first column with a lone control beside it — stated because a bare ordering rule gets "fixed" by the next reader who reads it as arbitrary. Its stored shape is **LibDBIcon's own `minimap` table** — the `hide` boolean the library owns and writes from its own menu — **not** a second key that would have to be kept in step with it; the label says *shown* and the boolean says *hidden*, so the row's get/set invert, which is the whole cost of storing the library's key and cheaper than the alternative. **Ripple:** `library-stack-§1` gains LibDataBroker-1.1 and LibDBIcon-1.0 as *always* rows and §2 loses LibDBIcon from the optional table; `standalone-windows` stops offering the launcher as an "and/or" beside the window verbs; `preview-mode` records that the launcher drives its existing switch rather than a copy of it; `options-ui-§5` says in as many words that the landing-page logo is not the icon file; new **anti-patterns #81** (no launcher, two launchers, a left-click on the panel where a rung exists, a right-click that is not the panel, a second `minimap.show` key, a broker enable setting) and **#82** (`IconTexture` at a Blizzard icon, a file id, or the right path in the wrong TGA format), `#1–#80` → `#1–#82`; `ADDONS.md` gains the rung column; `AUDIT.md`, `NEW_ADDON.md`, `NEW_ADDON_CONTEXT.md` and `EXECUTIVE_SUMMARY.md` follow. **What it obliges:** **all eleven addons are non-compliant until they adopt**, which is normal and expected for a new section — `launcher-§5` states adoption as five steps, and step 2 (the 128×128 logo) and step 3 (the object) **MUST land in one commit**, because an adopted launcher without its icon is a button that draws nothing, which is worse than the state before. Each addon also adds the two slash verbs as aliases onto the row it already has, and records its rung on the roster.

- **v2.51.0 (2026-09-16):** **The collection has a third repo kind, and `documentation-§8` is its rule set.** `library-stack-§7` carved out the Ka0s-owned **library** repo; nothing carved out the **documentation-and-tooling** repo — `WowAddonStandards` and `wow-addon`, which ship no Lua to the client and vendor no payload into any addon's `libs/`. `line-endings-§2` had recognised the kind since it was written (it is the *ships nothing to the client* half of the two-pin rule, naming *the standards and plugin repos* outright), but nothing said which of the other twenty-five sections reach such a repo. **The tell was a repo arguing with itself:** this one had accumulated three locally-ratified deviation rows — absent `docs/testing.md` and `smoke-tests.md`, a near-empty `DEPENDENCIES.md`, six `ARCHITECTURE.md` sections recorded *not applicable* — each individually reasonable and collectively a sign the standard was missing a scope, not that the repo was non-compliant. **§8 grants it once:** three applicability lists (applies unchanged, applies read here, does not apply) exhaustive over the Sections list and defaulting to *applies*, a substitutes list, and a **five-section `ARCHITECTURE.md`** — Overview, Module Map read as the file-and-path map, Known Limitations, `## Documentation map`, `## Documented deviations` — which **SHOULD NOT** carry the other five as *not applicable* rows, since that is the duplication the section ends. `documentation-§7` binds, with the honest content for a repo that needs almost nothing: a short required list and an explicit *not used here* list with reasons, never invented rows. `lint`, `testing`, `performance` and `automated-tests` do not apply **because there is no Lua**, and that is written as a statement about the tree with a stated trigger — *the first `.lua` this repo tracks outside a frozen bundle* — rather than a permanent grant. **Ripple:** `ADDONS.md` gains a third table and now lists this repo itself; `AUDIT.md` step 1 is **corrected**, not merely extended — it asserted that *a repo with no `.toc` is a Ka0s-owned library repo*, which is false for both documentation repos and had them graded against a rule set written for a Lua payload — and now resolves three kinds from a two-question discriminator it already had in hand for the line-ending pin. **What it obliges:** an audit of either documentation repo grades against §8 and **MUST NOT** file an absent `docs/testing.md`, an absent suite or a near-empty `DEPENDENCIES.md` as a finding; this repo retires its three deviation rows in favor of the rule.
- **v2.50.0 (2026-09-16):** **Bare `/<slash>` opens the settings panel; `/<slash> help` prints the command list.** `slash-commands-§4` had bare `/<slash>` print the help index, with a documented-deviation escape for browser-first addons that opened their main window instead. The collection owner changed it for every addon: an empty command now runs the reserved `config` verb, so the panel opens on its landing page (which renders the same `COMMANDS` table), and the list is `/<slash> help`. The dispatcher does this, not each addon: LibKa0s v1.38.0 (Slash minor 11) runs the host's `config` verb for an empty command and falls back to the help index only for a host with none. In combat the panel's own refusal is what bare `/<slash>` prints. The browser-first exception is dropped; `standalone-windows` now says so. **What it obliges:** every addon re-vendors LibKa0s v1.38.0, mirrors the new bare behavior in its library-absent Slash stub, and updates the tests, README and docs that described bare `/<slash>` as the help index. An addon that had mapped bare `/<slash>` to a window keeps that window on its `show` / `toggle` verbs.

Fused, **you could not find out what was hanging without committing to an interview about all of it**, and the observable result is a collection where a sweep is run when someone has an hour rather than when something changed. **So the command splits in two.** `/wow-addon:issue-audit` sweeps, reconciles each finding against the store by evidence hash, and files anything genuinely new as an open **`[untriaged]`** issue — **it never interviews and never changes code**. `/wow-addon:issue-triage` takes those `[untriaged]` issues, puts each to the maintainer with its verbatim evidence, and records the call on the issue — **it changes the issue store and nothing else**. The `[untriaged]` backlog between them stops being an unrecorded intention and becomes a countable quantity: the number of things found and not yet decided, visible in every listing. **Triage records rather than implements**, which is the one behavioral loss and is deliberate — accepting an item produces a `[deferred]` issue carrying the chosen approach, and the code change happens in an ordinary session against that issue, where it can be tested and reviewed like any other change rather than buried in the tail of a twenty-question interview. **An early stop is now free**: the queue already lives in the store, so stopping leaves the remainder `[untriaged]` and untouched, and nothing the user never saw is published to satisfy a run. **The four-value vocabulary is unchanged, and gains one absolute**: every issue **MUST** carry a `[status]` prefix at all times. There is no unprefixed state — an issue arriving without one (the GitHub web UI, a contributor who does not use these commands) is **repaired on sight** to `[untriaged]`, keeping its original title text, and **the repair is always announced**, including by the read-only listing commands, because a command people run to look at things must never change one quietly. **Two reporting commands complete the family**, both defaulting to the repo at the cwd like everything else: `issue-summary` answers *how much and where* (a status × repo grid, `unprefixed` column now retired along with the state), and the new `issue-details` answers *what* — status, GitHub state, title, a one-line description drawn from the issue body, and age, defaulting to the live `[untriaged]`+`[deferred]` store because printing 150 terminal issues buries the twenty that need a human. It **never invents a description**: a body with nothing usable gets `—` rather than a paraphrase of its own title. **Ripples.** `audit-review-history` rewritten to describe the pair and to state the records-not-implements consequence; the plugin gains `issue-triage` and `issue-details`, `issue-audit` loses its interview, branch and implement steps, `issue-summary` loses the `unprefixed` column and its collection-wide default, `fetch-issues` reports a missing prefix instead of tolerating it. **Minor bump, and one no repo can fail** — it changes what the commands do, not what an addon must contain.

- **v2.24.0 (2026-08-06):** **The standard mandated the exception and never the rule, and eleven repos wrote eleven different answers to a question nobody had asked.** automated-tests-§2 has required since v2.19.0 that a repo *"carve shell scripts out of a **CRLF-pinned repo**"* — a sentence that presumes a pin **no section anywhere states**, and that a repo satisfies perfectly by never pinning anything. A file holding **only** the `*.sh` carve-out **MUST NOT** count as satisfying it — that is the state that reads as handled in review and left 111 files disagreeing. **§2** — **two repo kinds, two pins.** A repo that ships Lua to the client, directly as an addon or vendored into an addon's client-bound `libs/`, pins `* text=auto eol=crlf`: the eight addon repos plus `LibKa0s`, whose ship folder lands in all eight `libs/` trees. A repo that ships **nothing** to the client pins `* text=auto eol=lf`: `WowAddonStandards` and `wow-addon`. CRLF exists in this collection for exactly one reason — the client — and where that reason is absent the pin follows the actual consumers, which are git, GitHub's renderer and shell tooling. The discriminator is mechanical and already in the playbook: `AUDIT.md` step 1 switches rule sets on the absence of a `.toc`. **§2 also forbids the per-path exemption** — `libs/** -text`, `tests/_kit/** -text`, a single `docs/<file>.md text eol=crlf` — which is why `LootHistory` is the 68-line, 102-straggler outlier; testing-§11's two gates already state their own representation carve-out and do not need a repo attribute to do it for them. **§3** — `*.sh text eol=lf` is mandatory in **both** kinds, including the LF repos where it is redundant, because a line you can satisfy by omission is the one that disappears the day someone edits the pin above it. The rationale is unconditional and is now stated **once**, here: a `#!/usr/bin/env bash` shebang followed by CRLF makes the kernel look for an interpreter literally named `bash\r` and every `case`/`in` line becomes a syntax error. **§4** — binary types **MUST** be marked `binary` rather than left to `text=auto`, whose detection is content-based: the live example is `realesrgan-x4plus-anime.param`, ncnn's plain-ASCII model definition sitting beside its own weights, which a CRLF pin would rewrite; `.bin` and `.param` appear in none of the nine existing files and `.tga` — the collection's **largest** binary population at 109 files — is missing from one of them. The list is deliberately ahead of the census, because a stale entry costs nothing and a missing one costs an asset. **§5 fixes one canonical file body per kind, verbatim, so a repo is diffed rather than read** — the two differ in the pin line, the paragraph declaring the repo's kind, and two word-level consequences of that; the `*.sh` block, the binary block and the renormalization recipe are byte-identical, so comparing a client-bound repo against a non-client one shows one decision instead of two documents. **§6 is the half that gets skipped**: attributes act on content only as it passes through git, so `git add --renormalize .` fixes the **INDEX** and does not rewrite bytes already on disk. A file written by `sed`, a Python generator, a WSL editor or a shell redirect stays LF in a CRLF repo, and git then emits `warning: in the working copy of 'X', LF will be replaced by CRLF the next time Git touches it` on **every** subsequent add — named verbatim in the section because it is the symptom a maintainer actually sees, and because being a warning rather than an error is precisely why it gets tuned out, leaving a repo with a policy, a clean `git status` and a tree that agrees with neither. It is cleared per file by `rm <path> && git checkout -- <path>`, verified with `file <path>`, and the change ends when `git add --renormalize .` stages nothing. **§7** makes it auditable, with the commands, and requires strays to be reported as **one** rolled-up finding carrying the command that produced the count. **Why none of this is cosmetic**, stated in the section rather than assumed: a CRLF shebang breaks the vendored runner for **everyone on every checkout** with an error that names the wrong thing; a whole-file ending flip buries a one-line change inside a diff of every line in the file, and at repo scale a **27,000-line** diff is not hard to review but impossible, so it is approved unread; and a vendored-copy `diff -r` gate goes red for a difference that is not a difference, training its readers to ignore the one gate that catches real drift. **Ripples.** `automated-tests-§2` stops presuming and starts **citing**: the carve-out is required unconditionally by `line-endings-§3` in **both** repo kinds, and *"Every other file in the collection is CRLF"* is deleted — it is now false of the two LF repos. - **v2.20.0 (2026-08-04):** **The complexity report now has a rule for what to do about it, and the collection learned what a shared library must refuse to absorb.** v2.18.0 fixed the *measurement* — one path, one invocation, a release checkpoint, a watch list with dispositions — and it worked exactly as designed for two releases, at which point a collection-wide sweep found what the design had not anticipated: **86 functions over CCN 15 across nine repos**, every one carrying a standing "accepted" disposition, one addon holding 20. Nothing was broken. Each entry had been a reasonable call in isolation, and the rule as written renews an acceptance by doing nothing. The result is a list that costs maintenance and carries no signal, because the next genuinely alarming function would arrive into a list of eighty-six and be indistinguishable from them. So **a disposition now has a shelf life** (performance-§10, automated-tests-§4, anti-pattern #53): carried as accepted across **three consecutive release runs**, an entry is either fixed or converted to a tracked deviation with an ID and an owner, and the watch list points at the tracker rather than re-arguing it every release. A watch list too long to read in one pass is itself the finding — that is a backlog, and a backlog needs scheduling rather than another disposition line. **Reading the number is now specified, because in Lua it does not mean what it means elsewhere (performance-§10).** `lizard` counts every `and` and `or` short-circuit as a decision, so twelve `t.k = rec.k or D.k` defaulting lines are **CCN 13 with no visible branching at all**, and a stack of `if not x then return end` guards scores the same way.

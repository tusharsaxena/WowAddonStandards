# Ka0s WoW Addon Standard (v2.88.0, 2026-10-24)

**Status:** Source of truth. All audit deviation reports and `NEW_ADDON_CONTEXT.md` template content derive from this standard. When the standard changes, bump the date and version at the top of this file.

**Adherence:** Every Ka0s addon **MUST** be built to this standard and **MUST** reference it: <https://github.com/tusharsaxena/WowAddonStandards> (see `documentation`, `toc-file-§1`).

**Audience:** future Ka0s and any agent (human or LLM) authoring or maintaining a Ka0s addon.

**Substrate:** Ace3. The ecosystem and Ka0s collection are aligned on it; deviations from Ace3 are case-by-case and must be justified.

**License:** MIT. Hostile licenses (`All Rights Reserved`) are forbidden.

## Reading this document

Each section uses these markers:

- **MUST** — non-negotiable; deviations are bugs.
- **SHOULD** — strongly preferred; deviations require a comment in code explaining why.
- **MAY** — optional; pick when it fits.
- **MUST NOT** / **SHOULD NOT** — forbidden patterns with cited reasons.

**Cross-references use the `filename-§N` scheme.** Every section lives in its own file under
`standards/standards/` and numbers its subsections **locally, from 1**. Reference a whole section by
its **bare filename** (e.g. `architecture`, `audit-review-history`); reference a subsection as
**`<filename>-§<n>`** (e.g. `architecture-§5`, `options-ui-§10`). This is the **only** cross-reference
form — the old global `§N.M` numbering is retired. When you add or reorder a section, update the
[Sections](#sections) list here.

**Reference implementations are described, not named.** This normative standard **MUST NOT** name a specific addon (from the Ka0s collection or the wider ecosystem) as a reference implementation. Instead it *describes* the implementation — what it does and how — in enough detail to be actionable on its own. This keeps the standard self-contained and durable when addons change or are renamed. The **named** research evidence behind these patterns (which real addons exhibit them) lives in the companion research document, `INDUSTRY_RESEARCH.md`, which is a standards-process input rather than part of the normative standard.

Where a Ka0s addon today already implements a rule well, it is called out as *"reference implementation (in the collection)"* with a description of the addon's role, never its name.

the stand-down does **not** reach the slash surface — every reserved verb, `config`, the bare `/<slash>` and the whole schema CLI keep answering while disabled (§2, a MUST), and only a **feature** verb SHOULD answer **one** tagged line naming `/<slash> enable`, or, under the `perf` hold alone, `Not available during a performance capture.`, chosen by which hold is taken and never by a bare stood-down check, while a key binding's press (launcher-§6) refuses as the toggle does — v2.56.0's narrowing to `enable` and `help` having been reversed in v2.57.0 and recorded as such in the section; the latch is `LibKa0s-Lifecycle-1.0`, shipping since LibKa0s **v1.40.0** with **v1.42.0** (Slash minor 14) the adoption floor; a mandated **conformance suite** (`tests/test_disabled.lua`) inside the green gate, audited step by step, whose step 6 proves each unconditional fire **reached** a handler by asserting `__fireUnconditional`'s returned count is at least 1; the library-absent Slash stub — minimal dispatch, no `FormatRow` copy, one verbatim library string (`DISABLED_LINE_FORMAT`, pinned with `Kit.assertLibraryConstant`), and the one library-absent line `%s is unavailable: the LibKa0s library did not load.`; mandatory cyan chat tag; settings read/write output format.

- **[debug-logging](standards/debug-logging.md)** — the on-screen debug console from `LibKa0s-DebugLog-1.0` (styled like the main window), not the chat frame, and resizable for the session only, as are its copy windows and the perf panel; what the log **MUST** cover, now including a **diagnosis checklist** (state edges, deferred work and its flush, refusals naming the guard, dependencies, caught errors), and the **quiet steady state** a repeating path keeps by logging only on change, through the console's own change gates and, for a state line written at enable, its at-enable queue; the **library's own lines** — the slash dispatcher's refusals, the combat lock's, the launcher's state and the stand-down latch's edges — written through the gated sink every host **MUST** hand to each `LibKa0s` descriptor that takes it, and never duplicated by the host; and the **diagnostics dump** every addon ships (§14), run by exactly `/<slash> diagnostics` and `/<slash> debug diagnostics` and by no alias (and by the console's orange **Diagnostics** link), turning debug logging on for the session unless the host opts out, live while the addon is disabled, appended through the ungated sink below the trace and never clearing it, secret-value safe, capped below the console buffer, and built on the library's helper rather than by hand.
- **[packaging](standards/packaging.md)** — `.pkgmeta`: vendored libs, no `externals:`, and an ignore list that is a **template whose entries bind only when the entry exists** — every root dot-entry the repo actually has, `.pkgmeta` itself included, the dev-only folders `docs/`, `tests/` and `_dev/`, plus `tools/` and the agent-tooling `.claude/` and `.superpowers/` **where the repo has them** — with the strong form's second branch narrowed to a comment saying why an entry is *deliberately packaged*, so a commented-out `ignore:` line beside a directory the repo actually has satisfies neither branch.
- **[line-endings](standards/line-endings.md)** — `.gitattributes` is mandatory in **every** repo, and the absent file is the defect: two pins, one per repo kind — `* text=auto eol=crlf` where the repo ships Lua to the client (the addons + a library vendored into their `libs/`), `* text=auto eol=lf` where it ships nothing to the client (the standards and plugin repos) — plus `*.sh text eol=lf` and `*.py text eol=lf` in **both**, binaries marked `binary`, one canonical file body per kind to diff against, the **§5 appendix** — the only thing that may sit below that body, carrying a path-keyed `binary` mark for a file no extension rule can reach — the vendored EOL gate `§7` now names rather than only supplying a command for, binding every repo that runs a suite while a suite-less documentation-and-tooling repo runs the hand check (e) instead — and, from LibKa0s test-kit revision 25 (LibKa0s v1.55.0), a **second case in that same gate** covering the body itself, so presence, the pin, the carve-outs and byte-identity with §5 stop being the audit's work every cycle; and the remediation rule that `git add --renormalize .` fixes the **index** and not the working tree.
- **[lint](standards/lint.md)** — `.luacheckrc`: config and the zero-error gate, with **the test tree in scope** — only `tests/_kit/` is excluded, being a vendored copy linted in its own repo, and the harness global is declared in a `files["tests/"]` stanza rather than in top-level `read_globals`.
- **[testing](standards/testing.md)** — headless Lua 5.1 test harness on the vendored `testkit` (`tests/_kit/`, never shipped); TDD; the green commit gate; **a gate closes a class of deviation only when it reads the whole of its own denominator**, so every gate states its scope and that scope is the whole set its own rule is about, enumerated from the tree rather than hand-listed, minus the carve-outs the rule names — `git ls-files` for a gate over the repository's files, the payload folder compared as a set for a vendored payload, with `LibKa0s`'s icon art compared against the consumer's declaration instead, the adopted module set for stub-surface parity; the three pinned load lists (TOC files, vendored library files, the suite list), where a declaration is the pair **(basename, directory)** — a kit suite is declared by its kit path, a same-basename consumer suite declared without one is a reported **collision** naming both paths and which is running, and an unreferenced kit suite file on disk is the same hole unless the repo recorded the decline as a `## Documented deviations` row, which reports it once as a decline rather than a failure — both reported by the kit from test-kit revision 25 (LibKa0s v1.55.0); `loadSuites` **raising** on a listed-but-absent suite rather than passing over it, which the kit does today, with a deliberate absence **declared** as a `pending` entry that registers as a skip carrying its reason; the conformance suites named at the point they are mandated — `tests/test_surface_parity.lua` for the stub-surface parity case, `tests/test_vendor_sync.lua` delegating to the kit rather than reimplementing it;

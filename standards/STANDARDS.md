# Ka0s WoW Addon Standard (v2.26.0, 2026-08-06)

**Status:** Source of truth. All audit deviation reports and `NEW_ADDON_CONTEXT.md` template content derive from this standard. When the standard changes, bump the date and version at the top of this file.

**Adherence:** Every Ka0s addon **MUST** be built to this standard and **MUST** reference it: <https://github.com/tusharsaxena/WowAddonStandards> (see `documentation`, `toc-file-§1`).

**Audience:** future Ka0s and any agent (human or LLM) authoring or maintaining a Ka0s addon.

**Substrate:** Ace3. The ecosystem and Ka0s collection are aligned on it; deviations from Ace3 are case-by-case and must be justified.

**License:** MIT. Hostile licenses (`All Rights Reserved`) are forbidden.

## Reading this document

Each section uses these markers:

- **MUST** — non-negotiable; deviations are bugs.
- **SHOULD** — strongly preferred; deviations require a comment in code explaining why.
- **MAY** — optional; pick when it fits.
- **MUST NOT** / **SHOULD NOT** — forbidden patterns with cited reasons.

**Cross-references use the `filename-§N` scheme.** Every section lives in its own file under
`standards/standards/` and numbers its subsections **locally, from 1**. Reference a whole section by
its **bare filename** (e.g. `architecture`, `audit-review-history`); reference a subsection as
**`<filename>-§<n>`** (e.g. `architecture-§5`, `options-ui-§10`). This is the **only** cross-reference
form — the old global `§N.M` numbering is retired. When you add or reorder a section, update the
[Sections](#sections) list here.

**Reference implementations are described, not named.** This normative standard **MUST NOT** name a specific addon (from the Ka0s collection or the wider ecosystem) as a reference implementation. Instead it *describes* the implementation — what it does and how — in enough detail to be actionable on its own. This keeps the standard self-contained and durable when addons change or are renamed. The **named** research evidence behind these patterns (which real addons exhibit them) lives in the companion research document, `INDUSTRY_RESEARCH.md`, which is a standards-process input rather than part of the normative standard.

Where a Ka0s addon today already implements a rule well, it is called out as *"reference implementation (in the collection)"* with a description of the addon's role, never its name.

## Sections

The normative standard, in reading order. **All of these are part of the standard — read every one.**
Reference a whole section by its filename, a subsection as `filename-§N`.

- **[layout](standards/layout.md)** — the single modular `core/ defaults/ settings/ locales/ modules/` layout + load order; folder casing; typed `media/` subfolders.
- **[toc-file](standards/toc-file.md)** — required TOC fields + exact field order; single latest-Retail Interface; `#`-sectioned file listing.

- **[architecture](standards/architecture.md)** — namespace bootstrap; AceAddon; module pattern; the closed message bus and the shape of addon it binds (two or more feature modules, or any module registering game events); schema-as-single-source.

- **[preview-mode](standards/preview-mode.md)** — placeholder-data preview/test mode for positionable displays.
- **[slash-commands](standards/slash-commands.md)** — AceConsole registration; schema-driven dispatch through `LibKa0s-Slash-1.0` over the addon's own `COMMANDS`; mandatory cyan chat tag; settings read/write output format.
- **[localization](standards/localization.md)** — metatable-fallback `NS.L`; English-string keys; locale-gated files; **match game data on stable IDs/tokens, never on localized display strings**; **US English as the source dialect for every authored string, comment, identifier, and doc**; and the two terminal states of the routing SHOULD — strings routed, or an English-only decision recorded as a deviation row.
- **[events-frames-taint](standards/events-frames-taint.md)** — AceEvent; combat lockdown; taint-safe Blizzard replacement; frame pooling; combat "secret" values.
- **[public-api](standards/public-api.md)** — versioned `NS.API.v1` surface (only if the addon exposes one).
- **[compat](standards/compat.md)** — a single `Compat` module owning every deprecated / cross-patch API call.
- **[debug-logging](standards/debug-logging.md)** — the on-screen debug console from `LibKa0s-DebugLog-1.0` (styled like the main window), not the chat frame.
- **[packaging](standards/packaging.md)** — `.pkgmeta`: vendored libs, ignore lists, no `externals:`.
- **[line-endings](standards/line-endings.md)** — `.gitattributes` is mandatory in **every** repo, and the absent file is the defect: two pins, one per repo kind — `* text=auto eol=crlf` where the repo ships Lua to the client (the addons + a library vendored into their `libs/`), `* text=auto eol=lf` where it ships nothing to the client (the standards and plugin repos) — plus `*.sh text eol=lf` in **both**, binaries marked `binary`, one canonical file body per kind to diff against, and the remediation rule that `git add --renormalize .` fixes the **index** and not the working tree.
- **[lint](standards/lint.md)** — `.luacheckrc`: config and the zero-error gate.
- **[testing](standards/testing.md)** — headless Lua 5.1 test harness on the vendored `testkit` (`tests/_kit/`, never shipped); TDD; the green commit gate; the three pinned load lists (TOC files, vendored library files, the suite list); the stub-surface parity case; the two vendored-payload gates — library-side kit-sync and consumer-side — and the skip as a third case status; characterization tests before a behavior-preserving refactor.
- **[performance](standards/performance.md)** — the vendored `LibKa0s-Perf-1.0` measurement harness; the two sanctioned bracket shapes and how the region's exits decide between them; declared buckets and observed containment; the `perf` verb; `<Addon>PerfDB`; the suspend/resume contract and the two-arm capture protocol; the offline scenario runner; the `lizard` complexity measurement and its release checkpoint; how to read a Lua complexity number (`and`/`or` count as decisions) and the permitted shapes for acting on one; and the **no-combat-path exemption** from the wiring MUST.
- **[automated-tests](standards/automated-tests.md)** — the consolidated record of the four out-of-game suites: frozen `docs/automated-tests/<run>/` bundles, the vendored `tests/_kit/run-automated-tests.sh`, what gates (lint, tests) and what only records (perf, complexity), `RESULTS.md` as the single-path trend line, the `ANALYSIS.md` write-up, and the **release gate** — all four suites plus zero CCN > 15 at the tag, which the commit gate deliberately is not.
- **[documentation](standards/documentation.md)** — root README + stub `CLAUDE.md` + `DEPENDENCIES.md` (the WSL2/Ubuntu toolchain contract), and no `CHANGELOG.md` at an addon root; the `docs/` trio (`ARCHITECTURE.md`, `testing.md`, `smoke-tests.md`); the **three-tier topic-detail model** — Tier 1 required and unconditional (`scope.md`, `module-map.md`, `schema.md`, `settings-panel.md`, `data-flow.md`, `common-tasks.md`), Tier 2 required per stated trigger under canonical names, Tier 3 addon-specific and free-form — with `ARCHITECTURE.md` as a capped hub carrying `## Documentation map` and `## Documented deviations`, the latter the single home of a ratified deviation; the player-facing README's canonical section order, its unlinked standard badge and its **MUST NOT** on a bundled-library inventory; the LibKa0s provenance line in root `CLAUDE.md`; the three-place standards reference, and how the standard itself is cited.

- **[versioning-git](standards/versioning-git.md)** — semver; trunk-based git workflow; commit only on green.
- **[naming-cheatsheet](standards/naming-cheatsheet.md)** — the naming conventions table.

## Changelog

- **v2.26.0 (2026-08-06):** **The decision record lived in the working tree, which is the one place a decision record cannot be reached from.** `/wow-addon:issue-audit` has written `docs/pending/LEDGER.md` since it existed — a tracked markdown table with a decision vocabulary, stable item IDs and an evidence hash per row — and across the collection it has accumulated **641 lines over eight repos** (`AbsorbTracker`, `BankLedger`, `ConsumableMaster`, `KickCD`, `LootHistory`, `PanelMaster`, `PrettyChat`, `WhatGroup`; `BuffTextNotifications`, `WhoGotLoots` and `LibKa0s` never had one), holding **247 rows: 148 `done`, 34 `wont-do` and 65 `deferred`**. The rows are good. The **store** is wrong, and wrong in a way no single repo shows you. **A deferral is a promise to revisit, and this one could only be revisited by whoever next ran the sweep in a clone** — it is not in the issue list the maintainer actually opens, nothing notifies on it, nothing links a commit or a PR to it, and it cannot be referenced from anywhere outside the repo it sits in. **PanelMaster carries 17 deferrals in its ledger and 8 open issues on its tracker**, two disjoint queues of the same kind of work, and the larger one is the invisible one. Meanwhile the terminal rows are pure weight: **182 of the 247 are `done` or `wont-do`**, settled forever, re-read on every sweep and re-diffed on every commit that touches the file. **So the store moves to GitHub issues on each addon's own repo, and `docs/pending/LEDGER.md` is retired and MUST be deleted.** **Status is carried as a title prefix, shaped exactly `[<Status>] <Title>`, over a closed four-value vocabulary** — `[done]` and `[will-not-do]` **closed**, `[deferred]` and `[untriaged]` **open**. The prefix, deliberately, is **not a label and not a milestone**: a label is a second object that has to be created per repo before it can be applied and silently no-ops when it wasn't, whereas the title is returned by every listing there is, so status survives a repo that nobody configured. GitHub's own open/closed state carries the terminal/live axis and the prefix carries which of the two closed and which of the two open reasons applies, which is exactly the information the old `Marker`/`Value` columns held. **Everything else about the sweep is unchanged** — the four discovery passes, the stable IDs, the evidence hashes that re-raise an item whose underlying text was rewritten, the bucketization by type and severity, the one-item-at-a-time interview, the branch decision, the implementation step and the report. Only the data store changed: what was a row is now an issue. **The migration carries the live rows and the reasoned refusals, and drops only the finished work.** The **65 `deferred`** rows become **open `[deferred]` issues** — 62 of them, since three in `BankLedger` are struck-through rows whose rationales read *DONE* and *SUPERSEDED*, the strikethrough carrying a meaning the `Decision` column never learned. The **34 `wont-do`** rows become **closed `[will-not-do]` issues**, which is not sentiment about tidiness: a `wont-do` rationale is a considered, argued refusal, it is what `harvest-standards` mines to find a rule the collection has collectively declined, it is what an audit reads as a recorded deviation, and **31 of the 34 are cited by a doc cross-reference somewhere in their own repo** — deleting the file without them would leave those pointers dangling and the reasoning recoverable only by `git show`. The **148 `done`** rows migrate **almost** nowhere: they are finished work, the commit that deletes the file preserves them in git history, and recreating 148 pre-closed issues would bury the 62 that are the entire point. The exception is mechanical rather than a matter of taste — **a `done` row that live documentation cites by id migrates too**, as a closed `[done]` issue, because the pointer is the thing being preserved and a pointer into a deleted file is worse than no pointer at all. In this collection that is **25 rows**, concentrated in `PanelMaster`, whose `DEPENDENCIES.md`, `artwork-spec.md`, `rendering.md` and `testing.md` cite `ARTWORK-01` through `ARTWORK-10` for design reasoning the code alone does not carry. **The rule generalises: migrate every row some other file names.** A repo whose docs cite nothing migrates deferrals and refusals only; one that reasons through ledger ids migrates those too, and the citation sweep is what tells the two apart rather than a judgment call per repo. No row anywhere is `untriaged`; that state is written only by an inventory-only run or an early stop, and the next sweep re-raises such an item from source regardless. **And the API path is now stated, because the wrong one is the observed default.** Issue work goes through the **`gh` CLI subcommands** — `gh issue list`, `gh issue create`, `gh issue edit`, `gh issue close`, `gh issue comment`, `gh issue view`, taking structured data via `--json` on those same subcommands — and **MUST NOT** go through `gh api graphql` or a hand-rolled query against `api.github.com/graphql`. Agents reach for GraphQL first, spend a round trip on a deprecated path, and fall back to the subcommand that would have worked; where REST is genuinely unavoidable it is `gh api repos/{owner}/{repo}/issues`, never the GraphQL endpoint. Because status is a **title prefix**, listing by status is a **title filter** over `gh issue list --json number,title,state` — not a label query, and not a search. **Ripples.** New subsection under **`audit-review-history`** carrying the store, the four-value table, the `gh` guardrail and the migration rule — appended, so no existing `filename-§N` reference moved. `documentation-§3`'s **single-home** rule keeps its full force and changes only where the reasoning may live: the register in `ARCHITECTURE.md` is still the one place a deviation is ratified, and the at-length reasoning moves from the ledger to the `[deferred]`/`[will-not-do]` issue, which the **Why** column now cites by issue number. `documentation-§3`'s `## Documentation map` drops `docs/pending/` from the frozen-directories list — the directory is gone, so a row naming it points at nothing, which the same section already makes a finding. `audit-review-history`'s "not ratified" list and `performance-§12`'s *"a decline reasoned only in the ledger is not an exemption"* take the same substitution. New **anti-pattern #60** (`#1–#59` → `#1–#60`) for the surviving ledger, which is not a harmless leftover but a **second and staler** answer to what was decided — the interview writes issues now and never touches the file, so a maintainer reading it sees deferrals closed months ago and misses every one filed since, and an agent grepping for prior decisions finds it **first**, because it is in the working tree and the issues are not. `AUDIT.md` gains the presence of `LEDGER.md` as a reportable finding and the `gh`-not-GraphQL line. `EXECUTIVE_SUMMARY.md` carries both edits. In the plugin: `issue-audit` (the store itself), `add-issue` and `fetch-issues` (the shared title-prefix vocabulary), `standards-audit` and `revendor-standards` (the retired file name). **`pending-audit` is renamed `issue-audit`**, the old name having described the file it wrote rather than the thing it operates on; and a new **`issue-summary`** reports the whole collection at once — a status × repo grid over every addon plus `WowAddonStandards`, `LibKa0s` and `wow-addon`, then the open issues per repo — which is the view the per-repo ledger could never produce and the clearest single argument for the move. **Minor bump, and a rule every repo can fail by standing still**: eight repos owe a deletion and 99 issues between them — 65 `[deferred]` open and 34 `[will-not-do]` closed, and the three without a ledger owe nothing but inherit the vocabulary the moment they run a sweep.

- **v2.25.0 (2026-08-06):** **Three edits to the README, and the common thread is that the page written for players had been quietly collecting facts addressed to somebody else.** The README is the only document in a Ka0s addon with a non-technical audience, and documentation-§1 has said so since v2.1.0. What it never said was what to do with the material that predates that rule, so three things stayed on the page by inertia: a bundled-library inventory, the LibKa0s provenance line, and a link on the standard badge. None of them is for a player, and one of them is now load-bearing somewhere else. **(1) The README MUST NOT carry a bundled-library inventory.** No `## Libraries`, `## Bundled libraries`, `## Libraries and credits`, `## Credits and libraries` or `## Credits and bundled libraries` — and no library roll-call written into the intro prose, which is where the rule was most often satisfied in letter and broken in fact. The Ace3 / LibSharedMedia / LibDataBroker / LibDBIcon list, the "everything ships inside it, nothing else to install" paragraph and the LibKa0s sentence all come out together. The reason is not tidiness: the list is **addressed to nobody**. The libraries ship inside the addon, so the player has nothing to install, nothing to choose and no decision the list informs, while the contributor who does need it reads `DEPENDENCIES.md` (documentation-§7) and `docs/ARCHITECTURE.md` (documentation-§3), which name every dependency with the evidence for it. The README copy was therefore a third statement of a twice-mandated fact on the one surface no gate has ever read — and it goes stale in the hardest direction to notice, since adding or dropping a library moves the TOC, `libs/` and `DEPENDENCIES.md`, all of which something reads, and leaves the README paragraph holding its old answer. **An OPTIONAL `## Credits` section is permitted and carries only external credit** — third-party artwork, another author's work, a font, a sound pack — never a vendored-library list; it becomes **item 13** of the canonical order, last, after `## Version History`, so the optional section has a defined position rather than landing wherever the deletion left a gap. An addon with nothing external to credit ships no `## Credits` at all, and a section deleted outright takes with it every link and cross-reference that pointed at its heading. **(2) The LibKa0s provenance line moves out of `README.md` and into root `CLAUDE.md`, and this is the half that is enforceable.** `Bundles [LibKa0s](https://github.com/tusharsaxena/LibKa0s) vX.Y.Z (MIT).` is now a required item of the documentation-§2 stub — **item 6**, in any addon that vendors `libs/LibKa0s/` — naming the **tag** the payload was copied from, moving in the **same commit** as the bytes. It is the input to testing-§11's consumer-side vendored-payload gate, which resolves that tag in the sibling checkout and compares both payloads against it, and as of **LibKa0s v1.8.1 / testkit revision 9** `tests/_kit/vendor_sync.lua` reads it out of **`CLAUDE.md`** through a named `provenanceFile` opt, with the Lua pattern `[Bb]undles %[LibKa0s%]%b() (v[%d%.]+)` — so a standalone sentence and a mid-sentence phrasing both satisfy it. **There is no fallback to `README.md`, deliberately**: a repo that re-vendors the new kit and leaves its line where it was reads as carrying **no provenance line at all** and the case fails, naming `CLAUDE.md`. A fallback would let a repo sit half-migrated with two lines that can disagree and a gate silently preferring one of them, which is the drift the gate exists to catch. This is what makes edit (1) safe to state as a MUST NOT: without the kit revision, deleting the library section from a README would have reddened the gate in every addon at once. **(3) The standard badge loses its link.** documentation-§1's badge table row 4 becomes the bare `![Standard](https://img.shields.io/badge/Ka0s-WoW_Addon_Standard-yellow)`, with a **MUST NOT** on re-wrapping it — the same shape, and for the same reason, as the `_`-not-`%20` bullet directly above it, which exists because someone "corrected" that one back. The standards-repo reference that actually binds an addon lives in the other two of documentation-§6's three places: the TOC `## X-Standard:` field and the root `CLAUDE.md` `## Standards compliance (read first)` section. The badge is the third, and its job there is to **declare**, not to navigate: a player who follows the link lands in a document that tells them nothing about the addon they installed, and the contributor who needs the repo already has it in the two files they open first. documentation-§6 item 2 stops describing the badge as *"the badge/line linking the standard"* and says what it is. **Ripples.** `library-stack-§7`'s **Vendor sync (MUST)** gains the provenance line as the tag the gate compares against, in `CLAUDE.md` rather than `README.md`, moving in the same commit as the bytes in both directions. `testing-§11`'s consumer-side gate names where its `<ref>` comes from and states the no-fallback rule and its consequence — a missing line is a **failure**, not the skip an absent sibling checkout earns, because the repo had everything it needed to answer. New **anti-patterns #58** (a vendored-library inventory in the player-facing README) and **#59** (the provenance line left in `README.md` after kit revision 9), `#1–#57` → `#1–#59`; the two are separated deliberately, since #58 is an unread paragraph and #59 is a red gate. `NEW_ADDON_CONTEXT.md`'s item 20a carries the unlinked badge template, the canonical order through the optional `## Credits`, and the no-inventory MUST NOT; its `CLAUDE.md` starter stub carries the provenance line; its DoD checklist gains both. `NEW_ADDON.md` step 6 stops saying *"the standard-link badge"*. `EXECUTIVE_SUMMARY.md` and the index blurbs for `documentation` and `library-stack` follow. **Minor bump, and one every addon in the collection owes at once** — the three edits are a single README-and-`CLAUDE.md` pass per repo, but edit (2) must land in the same commit as the testkit revision-9 re-vendor and the regenerated `docs/test-cases.md`, because the first case's name changed with the file it reads. Drawn from LibKa0s v1.8.1, which moved the gate first and left the standard describing a file the gate no longer opens.

- **v2.24.0 (2026-08-06):** **The standard mandated the exception and never the rule, and eleven repos wrote eleven different answers to a question nobody had asked.** automated-tests-§2 has required since v2.19.0 that a repo *"carve shell scripts out of a **CRLF-pinned repo**"* — a sentence that presumes a pin **no section anywhere states**, and that a repo satisfies perfectly by never pinning anything. The measured collection is what that produces. **`PanelMaster` carries a five-line `.gitattributes` holding the `*.sh` carve-out and nothing else**, and **111 of its 185 tracked text files** sit LF in the working tree against the collection's evident intent — the exception adopted, the rule never stated, and no gate anywhere that can tell. **`WowAddonStandards` and `wow-addon` carry no `.gitattributes` at all**, so every checkout of the repo that publishes this standard, and of the plugin whose own hook script the kernel will refuse to run if it ever arrives CRLF, gets whatever `core.autocrlf` the local git happens to hold. The remaining eight — `LibKa0s`, `AbsorbTracker`, `BankLedger`, `ConsumableMaster`, `KickCD`, `LootHistory`, `WhatGroup`, `prettychat` — had each **hand-written the same policy**, correctly, into files of **34, 36, 34, 35, 22, 31, 68 and 30 lines**: one policy, eight documents, none of which can be diffed against another. And the working trees disagree with their own repos' stated intent in every one of the nine that state anything — stragglers at **LibKa0s 2, AbsorbTracker 9, BankLedger 3, ConsumableMaster 15, KickCD 9, LootHistory 102, PanelMaster 111, WhatGroup 3, prettychat 3**. **New section [line-endings](standards/line-endings.md), placed after `packaging`.** **§1** — every repo **MUST** carry an explicit root `.gitattributes`, and **the absent file is the defect rather than a neutral default**: with no attributes the bytes on disk are decided by a per-machine `core.autocrlf`/`core.eol` that is invisible to everyone but its owner, so two contributors produce byte-different checkouts of the same commit, neither is doing anything wrong, and there is no conversation in which the disagreement surfaces. A file holding **only** the `*.sh` carve-out **MUST NOT** count as satisfying it — that is the state that reads as handled in review and left 111 files disagreeing. **§2** — **two repo kinds, two pins.** A repo that ships Lua to the client, directly as an addon or vendored into an addon's client-bound `libs/`, pins `* text=auto eol=crlf`: the eight addon repos plus `LibKa0s`, whose ship folder lands in all eight `libs/` trees. A repo that ships **nothing** to the client pins `* text=auto eol=lf`: `WowAddonStandards` and `wow-addon`. CRLF exists in this collection for exactly one reason — the client — and where that reason is absent the pin follows the actual consumers, which are git, GitHub's renderer and shell tooling. The discriminator is mechanical and already in the playbook: `AUDIT.md` step 1 switches rule sets on the absence of a `.toc`. **§2 also forbids the per-path exemption** — `libs/** -text`, `tests/_kit/** -text`, a single `docs/<file>.md text eol=crlf` — which is why `LootHistory` is the 68-line, 102-straggler outlier; testing-§11's two gates already state their own representation carve-out and do not need a repo attribute to do it for them. **§3** — `*.sh text eol=lf` is mandatory in **both** kinds, including the LF repos where it is redundant, because a line you can satisfy by omission is the one that disappears the day someone edits the pin above it. The rationale is unconditional and is now stated **once**, here: a `#!/usr/bin/env bash` shebang followed by CRLF makes the kernel look for an interpreter literally named `bash\r` and every `case`/`in` line becomes a syntax error. **§4** — binary types **MUST** be marked `binary` rather than left to `text=auto`, whose detection is content-based: the live example is `realesrgan-x4plus-anime.param`, ncnn's plain-ASCII model definition sitting beside its own weights, which a CRLF pin would rewrite; `.bin` and `.param` appear in none of the nine existing files and `.tga` — the collection's **largest** binary population at 109 files — is missing from one of them. The list is deliberately ahead of the census, because a stale entry costs nothing and a missing one costs an asset. **§5 fixes one canonical file body per kind, verbatim, so a repo is diffed rather than read** — the two differ in the pin line, the paragraph declaring the repo's kind, and two word-level consequences of that; the `*.sh` block, the binary block and the renormalization recipe are byte-identical, so comparing a client-bound repo against a non-client one shows one decision instead of two documents. **§6 is the half that gets skipped**: attributes act on content only as it passes through git, so `git add --renormalize .` fixes the **INDEX** and does not rewrite bytes already on disk. A file written by `sed`, a Python generator, a WSL editor or a shell redirect stays LF in a CRLF repo, and git then emits `warning: in the working copy of 'X', LF will be replaced by CRLF the next time Git touches it` on **every** subsequent add — named verbatim in the section because it is the symptom a maintainer actually sees, and because being a warning rather than an error is precisely why it gets tuned out, leaving a repo with a policy, a clean `git status` and a tree that agrees with neither. It is cleared per file by `rm <path> && git checkout -- <path>`, verified with `file <path>`, and the change ends when `git add --renormalize .` stages nothing. **§7** makes it auditable, with the commands, and requires strays to be reported as **one** rolled-up finding carrying the command that produced the count. **Why none of this is cosmetic**, stated in the section rather than assumed: a CRLF shebang breaks the vendored runner for **everyone on every checkout** with an error that names the wrong thing; a whole-file ending flip buries a one-line change inside a diff of every line in the file, and at repo scale a **27,000-line** diff is not hard to review but impossible, so it is approved unread; and a vendored-copy `diff -r` gate goes red for a difference that is not a difference, training its readers to ignore the one gate that catches real drift. **Ripples.** `automated-tests-§2` stops presuming and starts **citing**: the carve-out is required unconditionally by `line-endings-§3` in **both** repo kinds, and *"Every other file in the collection is CRLF"* is deleted — it is now false of the two LF repos. A watch list too long to read in one pass is itself the finding — that is a backlog, and a backlog needs scheduling rather than another disposition line. **Reading the number is now specified, because in Lua it does not mean what it means elsewhere (performance-§10).** `lizard` counts every `and` and `or` short-circuit as a decision, so twelve `t.k = rec.k or D.k` defaulting lines are **CCN 13 with no visible branching at all**, and a stack of `if not x then return end` guards scores the same way. A high number in Lua usually means *this function defaults or guards a lot of fields*, not *this function has tangled control flow* — and the sweep's worst offender, a 40-branch `Sanitize`, was one flat list of `or` defaults that was never hard to read, while a 19-branch function with four nested loops was. The metric ranks them backwards, and an agent that does not know this reads the report inverted and "fixes" the wrong function. **New performance-§11 governs acting on a finding**, which the standard had left entirely open even while mandating the report: four permitted shapes (module-level table-driven dispatch; a named helper for a nameable block; a data table plus one loop; splitting a builder into N builders), a prohibition on the metric-gaming extraction that lowers CCN and raises confusion (anti-pattern #52 — the tell is the helper's **name**: `part2` and `doTheRest` were extracted for the number), a prohibition on the per-call allocation that a naive table-driven rewrite introduces on a per-frame path (#43's trade, made backwards), and a MUST NOT on changing behavior — including fixing a bug noticed in passing, because a behavior change hidden inside a large mechanical diff is unreviewable. **New testing-§13** supplies what makes any of it verifiable: a **characterization test written before the refactor and run against the unrefactored code**, because a test written afterwards asserts whatever the new code happens to do. The sweep found **16 of 86** warned functions with no coverage at all — by construction the ones a refactor is least safe to attempt and most likely to be aimed at, since complexity and untestedness have the same cause. **New savedvariables-§5 and anti-pattern #54** close a defect the refactor work would otherwise have introduced at scale: `t.k = stored.k or D.k` cannot distinguish *unset* from *set to `false`*, from `""`, or from an empty set, so the user turns an option off and it returns, clears a custom path and the shipped one comes back, deselects every entry in a set and the full selection reappears. It hides well because `0` is truthy in Lua — every numeric field a reader spot-checks behaves — and it puts the addon at odds with AceDB underneath it, whose defaults merge follows `nil`-ness and restores the `false` the addon's `or` layer then overrides. **And library-stack-§7 gains the counterweight to anti-pattern #47.** The standard said "don't hand-roll what LibKa0s provides" and said nothing about the opposite failure, which is harder to reverse because the additive-only rule makes a wrong abstraction surface the library keeps forever. Three bars now: 2+ consumers with the same **semantics** (not the same shape), **no per-consumer escape hatches** (those flags are the consumers' divergence re-encoded as configuration, and the library now owns a decision it cannot make), and a stable abstraction rather than a coincidence of today's code. Plus the rule that catches the most tempting mistake: **MUST NOT promote on frequency alone** — the collection's most-repeated shape is the optional-object guard at **400+ sites across nine repos**, and it must stay inline, because a `CallIf` helper turns a compile-time call into a stringly-typed lookup invisible to `grep` and `luacheck` and erases the three distinct reasons those guards exist. The worked rejection is the schema-migration runner (anti-pattern #55), nominated from eight repos holding **five incompatible variants** that disagree on who stamps `schemaVersion`, when, and whether a failed step still stamps — needing five escape hatches to own an eight-line loop, with silent SavedVariables corruption as the downside. **Duplication was the cheaper answer**, and the complexity win it was nominated for was available locally anyway. The underlying disagreement is recorded in `open-evolutions` as a ruling the standard still owes, together with the AceDB trap that makes it hard: the defaults merge backfills `schemaVersion` to current the moment `db.global` is first read, so the stamp alone cannot tell a fresh install from a legacy account. **Minor bump.** Nothing an addon ships becomes non-compliant on adoption: §11 and testing-§13 constrain a refactor only once you undertake one, and the disposition shelf life first bites at an addon's third release run after adoption. What changes immediately is that `or`-defaulting a falsy-meaningful field is now a named anti-pattern rather than a style preference. Drawn from a nine-repo `feat/fix-ccn` sweep that read all 86 warned functions in full before proposing a single edit — which is also how the `and`/`or` tax and the five-variant migration divergence were found, neither being visible from any one repo.

- **v2.12.0 (2026-07-30):** **Performance measurement becomes part of the standard, carried by a Ka0s-owned vendored library rather than per-addon code.** New section **[performance](standards/performance.md)** (added to the Sections list, after `testing`) makes ten things normative. The premise is that WoW's built-in Addon Profiler **cannot** answer *"is this cost even ours?"* — it bills a **shared** library's dispatch frame to whichever addon **created** it, so enabling and disabling addons moves the blame around and the first-alphabetical Ace addon absorbs its siblings' cost — so the only trustworthy answer is an A/B on the **same fight** with load order and shared-frame ownership held fixed. **performance-§1** — every addon **MUST** vendor **`LibKa0s-Perf-1.0`** under `libs/LibKa0s/`, create **one instance per addon at load** from a descriptor in `core/PerfSetup.lua` (`NS.Perf = LibStub("LibKa0s-Perf-1.0"):New(descriptor)`), positioned in the TOC **before** any module taking `NS.Perf` as a load-time upvalue, and degrade to a stub carrying every member the addon actually calls when the lib is absent; **MUST NOT** hand-roll a private probe, and **MUST NOT** let the lib share a frame between hosts. **performance-§2** — the gated bracket idiom `local t0 = Perf.on and debugprofilestop()` … `if t0 then Perf.Note(key, debugprofilestop() - t0) end` is pinned as the **only** form: one upvalue read, one field read, one boolean test when capture is off, with a hard **MUST NOT** on allocating/calling/formatting inside a dormant bracket, and the offline zero-overhead scenario as **required evidence** rather than a comment claiming it. **performance-§3** — buckets are **declared** in the descriptor in report order, nesting is declared with `within` rather than explained in prose, nested totals **MUST NOT** be summed, and a declared bucket no bracket reaches is *"a lie in every report"* that the addon's own suite MUST pin. **performance-§4** — **`perf` is a reserved slash verb** (slash-commands-§2) dispatched through the addon's own `NS.COMMANDS` (slash-commands-§3) and **never registered by the library**, which returns lines the host prints; a bare `/<slash> perf` **MUST** be the entry point to a run and **SHOULD** open a guided step panel offering only the next legal step, because ordering silently ruins captures and a numbered chat list scrolls away the moment combat starts. **performance-§5** — **`<Addon>PerfDB`**, a bounded capture ring, **MUST** live outside the AceDB tree so it never rides profile copy/reset/switch. **performance-§6** — the **suspend/resume host contract**: inert **without a `/reload`** (reloading shifts frame ownership, the confound itself), visibility enforced **at the source** in the show-decision ladder rather than by hiding frames (hidden frames come back and the suspended arm then measures the addon still working), restore from **current** state, never persist the flag, and **resume before saving or reporting** so a persistence error cannot strand the addon inert. **performance-§7** — the **capture protocol**: clean arm first, suspend as the finer second arm, windows opened on the player's combat **state** rather than the combat *events* (suspend unregisters the event frames, so the suspended arm would never see `PLAYER_REGEN_DISABLED`), no comparing arms across different addon sets or a `/reload`, and the **buckets** read as the addon's cost with the frame-time delta treated as unresolved below the harness's measured spread. **performance-§8** — record schema and the standing, cumulative **`docs/perf-runs/`** store, where a committed capture is evidence that outlives the write-up interpreting it. **performance-§9** — **`tests/perf.lua`**, the offline scenario runner: outside the green gate, asserting **only** deterministic quantities (API calls, bytes allocated), with a hard **MUST NOT** on wall-clock assertions. **performance-§10** — `lizard` complexity as a committed **report-only** `docs/complexity.md`, explicitly **not** gating. Adoption strength is **MUST for the wiring, SHOULD for coverage** — which paths get buckets is addon-specific, but uniform wiring is what makes *"run `/<slash> perf` and send me the JSON"* true of any Ka0s addon. **Cross-section ripples:** new **library-stack-§7 (Ka0s-owned shared libs)** — the `LibKa0s` umbrella vendored exactly as Ace3 is, **one LibStub major per module**, additive-only contracts, plus the two rules that only bite when the library's author and its consumers are the same person: a **vendor-sync MUST** (the vendored copy byte-identical to the source repo's ship folder, `diff -r` empty, a **re-vendor commit in every consumer** per library change, ideally its own commit) and a **module-versioning MUST** (a LibStub **minor per file** bumped on every released change, never in lockstep, files paired by version not merely by presence, a published registry of live per-file minors, the lib repo's semver kept as a separate axis, and the bump↔changelog coupling made mechanical).

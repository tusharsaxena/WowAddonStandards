# Ka0s WoW Addon Standard (v2.65.0, 2026-09-23)

**Status:** Source of truth. All audit deviation reports and `NEW_ADDON_CONTEXT.md` template content derive from this standard. When the standard changes, bump the date and version at the top of this file.

**Adherence:** Every Ka0s addon **MUST** be built to this standard and **MUST** reference it: <https://github.com/tusharsaxena/WowAddonStandards> (see `documentation`, `toc-file-§1`).

**Audience:** future Ka0s and any agent (human or LLM) authoring or maintaining a Ka0s addon.

**Substrate:** Ace3. The ecosystem and Ka0s collection are aligned on it; deviations from Ace3 are case-by-case and must be justified.

**License:** MIT. Hostile licenses (`All Rights Reserved`) are forbidden.

## Reading this document

Each section uses these markers:

- **MUST** — non-negotiable; deviations are bugs.
- **SHOULD** — strongly preferred; deviations require a comment in code explaining why.
- **MAY** — optional; pick when it fits.
- **MUST NOT** / **SHOULD NOT** — forbidden patterns with cited reasons.

**Cross-references use the `filename-§N` scheme.** Every section lives in its own file under
`standards/standards/` and numbers its subsections **locally, from 1**. Reference a whole section by
its **bare filename** (e.g. `architecture`, `audit-review-history`); reference a subsection as
**`<filename>-§<n>`** (e.g. `architecture-§5`, `options-ui-§10`). This is the **only** cross-reference
form — the old global `§N.M` numbering is retired. When you add or reorder a section, update the
[Sections](#sections) list here.

**Reference implementations are described, not named.** This normative standard **MUST NOT** name a specific addon (from the Ka0s collection or the wider ecosystem) as a reference implementation. Instead it *describes* the implementation — what it does and how — in enough detail to be actionable on its own. This keeps the standard self-contained and durable when addons change or are renamed. The **named** research evidence behind these patterns (which real addons exhibit them) lives in the companion research document, `INDUSTRY_RESEARCH.md`, which is a standards-process input rather than part of the normative standard.

Where a Ka0s addon today already implements a rule well, it is called out as *"reference implementation (in the collection)"* with a description of the addon's role, never its name.

Visibility is one Master-controls row stored at **LibDBIcon's own `minimap.hide`**, never a second key, and a player's choice there is a **per-installation display preference that MUST survive both *Reset all settings* and a page-scoped Defaults button** — an addon whose reset would reach the row exempts that one row. The icon is the addon's own logo, the same file the TOC names, and the object's **`label` is the brand name in plain text (`Ka0s <Name>`)** — never the TOC `## Title`, which may carry color escapes, and never the folder name, so the collection groups together in a broker display.

- **[events-frames-taint](standards/events-frames-taint.md)** — AceEvent, the two permitted private frames (a `RegisterUnitEvent` filter for the one or two units that call accepts, with the three conditions that keep it one; and, for an addon that embeds no AceEvent-3.0 at all, one lazily created boundary watcher for the combat edges, stood down fully and listed in `## Event Subscriptions`) and the registration block that survives a retired event name — per-event isolation through `LibKa0s-Core-1.0`'s `SafeRegisterEvent` family from LibKa0s v1.56.0, plus a host-owned, player-reachable record of what the client rejected; combat lockdown; taint-safe Blizzard replacement; frame pooling; combat "secret" values.
- **[public-api](standards/public-api.md)** — versioned `NS.API.v1` surface (only if the addon exposes one).
- **[compat](standards/compat.md)** — a single `Compat` module owning every deprecated / cross-patch API call, which **MAY** route a member through `LibKa0s-Compat-1.0`; required only of an addon that makes such a call outside `LibKa0s`'s majors, and a dead library-absent rung is deleted rather than shimmed.
- **[debug-logging](standards/debug-logging.md)** — the on-screen debug console from `LibKa0s-DebugLog-1.0` (styled like the main window), not the chat frame.
- **[packaging](standards/packaging.md)** — `.pkgmeta`: vendored libs, no `externals:`, and an ignore list that is a **template whose entries bind only when the entry exists** — every root dot-entry the repo actually has, `.pkgmeta` itself included, the dev-only folders `docs/`, `tests/` and `_dev/`, plus `tools/` and the agent-tooling `.claude/` and `.superpowers/` **where the repo has them** — with the strong form's second branch narrowed to a comment saying why an entry is *deliberately packaged*, so a commented-out `ignore:` line beside a directory the repo actually has satisfies neither branch.
- **[line-endings](standards/line-endings.md)** — `.gitattributes` is mandatory in **every** repo, and the absent file is the defect: two pins, one per repo kind — `* text=auto eol=crlf` where the repo ships Lua to the client (the addons + a library vendored into their `libs/`), `* text=auto eol=lf` where it ships nothing to the client (the standards and plugin repos) — plus `*.sh text eol=lf` and `*.py text eol=lf` in **both**, binaries marked `binary`, one canonical file body per kind to diff against, the **§5 appendix** — the only thing that may sit below that body, carrying a path-keyed `binary` mark for a file no extension rule can reach — the vendored EOL gate `§7` now names rather than only supplying a command for — and, from LibKa0s test-kit revision 25 (LibKa0s v1.55.0), a **second case in that same gate** covering the body itself, so presence, the pin, the carve-outs and byte-identity with §5 stop being the audit's work every cycle; and the remediation rule that `git add --renormalize .` fixes the **index** and not the working tree.
- **[lint](standards/lint.md)** — `.luacheckrc`: config and the zero-error gate, with **the test tree in scope** — only `tests/_kit/` is excluded, being a vendored copy linted in its own repo, and the harness global is declared in a `files["tests/"]` stanza rather than in top-level `read_globals`.
- **[testing](standards/testing.md)** — headless Lua 5.1 test harness on the vendored `testkit` (`tests/_kit/`, never shipped); TDD; the green commit gate; **a gate closes a class of deviation only when it reads the whole of its own denominator**, so every gate states its scope and that scope is the whole set its own rule is about, enumerated from the tree rather than hand-listed, minus the carve-outs the rule names — `git ls-files` for a gate over the repository's files, the payload folder compared as a set for a vendored payload, the adopted module set for stub-surface parity; the three pinned load lists (TOC files, vendored library files, the suite list), where a declaration is the pair **(basename, directory)** — a kit suite is declared by its kit path, a same-basename consumer suite declared without one is a reported **collision** naming both paths and which is running, and an unreferenced kit suite file on disk is the same hole unless the repo recorded the decline as a `## Documented deviations` row, which reports it once as a decline rather than a failure — both reported by the kit from test-kit revision 25 (LibKa0s v1.55.0); `loadSuites` **raising** on a listed-but-absent suite rather than passing over it, which the kit does today, with a deliberate absence **declared** as a `pending` entry that registers as a skip carrying its reason; the conformance suites named at the point they are mandated — `tests/test_surface_parity.lua` for the stub-surface parity case, `tests/test_vendor_sync.lua` delegating to the kit rather than reimplementing it; the two vendored-payload gates — library-side kit-sync and consumer-side — and the skip as a third case status; characterization tests before a behavior-preserving refactor; and the green gate's **speed** as a governed property — measure before optimizing, never re-parse source already read, never spawn one process per item, and parallelism last and opt-in; and every out-of-game run **bounded** — per-process and process-tree memory, wall clock, re-launch depth, per-case heap and CPU budgets and a leak gate, all from the vendored kit, with no suite doing work at load or naming a host path.
- **[performance](standards/performance.md)** — the vendored `LibKa0s-Perf-1.0` measurement harness; the two sanctioned bracket shapes and how the region's exits decide between them; declared buckets and observed containment; the `perf` verb; `<Addon>PerfDB`; the suspend/resume contract and the two-arm capture protocol; the **perf analysis bundle** — one frozen `docs/perf-analysis/<YYYYMMDD-HHMMSS>/` per in-game capture, carrying the report, the verbatim record and the `ANALYSIS.md` reading of it together, stamped from the record's own timestamp; the offline scenario runner; the `lizard` complexity measurement and its release checkpoint; how to read a Lua complexity number (`and`/`or` count as decisions) and the permitted shapes for acting on one; and the **no-combat-path exemption** from the wiring MUST.

## Changelog

- **v2.65.0 (2026-09-23):** **The 2026-09-23 review-and-audit remediation.** **(1) `AUDIT.md`'s re-vendor bundle check grades by step 5, counts same-day commits, and reads a consolidated span bundle; `audit-review-history` defines that bundle.** Seven audits in the 2026-09-23 sweep tripped over the same check. It hard-coded **High** for an unrecorded re-vendor tag twice, while step 5's impact table reserves High for what a user, their SavedVariables or their session can hit and grades a doc-only gap **Low**; auditors ended up recording both grades on one entry. - **v2.43.0 (2026-09-12):** **`architecture-§5`'s one-helper MUST now binds schema rows, a structural registry no row can address goes through one registry writer the addon names instead, and every other write outside the helper still needs its register row.** The rule said every mutation goes through `NS.Schema:Set(path, value)`, and a path is the only thing that helper takes. For a collection the player builds — AuraMaster's containers, MultiMeters' windows, PanelMaster's panels, KickCD's per-spec spell lists — the mutations that matter have no path: *"container 7 exists"* is not a leaf, and no row can be written that names it. So the MUST could be met in one of two ways, both bad: bolt a registry address onto the helper that exists only to pass the audit, or carry a register row, forever, in every addon with a user-built collection. A survey of all ten rostered addons, corrected by the rollout that applied the final text to each one's code, found **seven** holding such a registry. **None** routes membership through its helper. **Five of the seven** had already converged unasked on what the rule should have said — one module owns the collection and everything else calls it — and **two** had a register row for it: AuraMaster, and LootHistory, whose row mixes its id sets with state that is not a registry.

  **What the section now says.** The helper MUST carry every write to a **schema-row path** — whole-section writes and instance-relative rows inside a registry member included, so nothing a row addresses gets a new way around it. Beside it sits a new MUST: every membership change of a **structural registry** — create, delete, duplicate — and its **identity and bookkeeping** (order, the id counter, the storage key, a stamped id, a frame name, a lookup-key name, the seeding sentinel; a closed list) go through **one registry writer**, named in `ARCHITECTURE.md` → Settings Schema. A registry is defined by three tests an auditor applies to the data rather than to intent: the player adds and removes members; the defaults ship it empty or seeded rather than enumerated; the helper takes no path for it — no row names a member's existence and no whole-value path writes the collection in one call. A flat collection the helper does take whole, at a normalized path, is a value; an addon **MAY** choose that route over a writer, and both are compliant. A fixed-membership list the player only reorders fails the first two and stays a value, written through the helper or carried by a register row. **The load pass is decided explicitly, because four of the seven registries have one that writes them**: the migration runner and any profile-prepare step called with it — AuraMaster's `Database.PrepareProfile`, MultiMeters' `Database.SeedWindows`, KickCD's `MigrateSpecKeys` (with `BuildSpells` as the seed routine), PanelMaster's `SweepPreviewPanels` — **MAY** write the registry directly. It runs before any reader has seen the data, so there is nothing for `onChange` to tell; it is named beside the writer, its entry points are reachable only from initialization and AceDB's profile callbacks, and it repairs and seeds rather than applying a choice. A registry reset verb is a writer operation and **MAY** reuse the load pass's seed routine. Wholesale replacement — the options-ui-§12 reset, AceDB's swap and copy — is not a registry write at all. **The guards that keep it from being a loophole** are all tests on the data. A row inside a member still goes through the helper even when the registry writer is the caller, and the helper must be able to reach a member that is not the current one. Where a field is both a key and a row, the row wins. A preference the player sets on a member is a setting, not the writer's: with no row it is a missing row and needs one, or a register row. Persistent state that is neither a row nor registry bookkeeping — geometry only a drag writes, on a member or not, and a remembered view — keeps the register row it needed before. So **options-ui-§13 is promoted from MAY to MUST** and the section gains four new siblings, **§15–§18**, all of them written to be checked by **reading the schema** rather than by looking at the screen. **(1) §13 — every page draws a strip, including a one-section page.** A renderer's fallback to the untabbed form below some tab count is retired: it made a page's chrome a function of how many sections it happened to hold, so merging two sections into one deleted the strip as a side effect of an edit about something else. The exemption is written as a property of the **call graph** — a page the host does not render through the flow engine, which today is **two** pages and both of them, the AceConfig-drawn Profiles sub-page and the host-drawn landing page — rather than as a page name, because a name-match stops being true the first time a page is renamed and says nothing when it does. The property is also what makes it two rather than one: an enumeration written from the Profiles page alone was wrong about the landing page the day it was written, which is why every restatement of the exemption names both. §13 also gains a **wrap-stability** rule out of a reproducible bug: on a page with thirteen tabs over three wrapped rows, selecting one particular tab opened a gap between the rows and moved and resized the content panel below. The cause generalizes and so does the rule — the row pitch was being read off whichever tab had been drawn first, and a selected tab is drawn from a **different atlas** than an unselected one, so the geometry became a function of the selection. Measure once, from a state no click can change, and pin the **invariant** (identical band, identical row offsets, every selection) rather than the mechanism — with a harness that answers a different height per atlas, because one that does not cannot fail the case. **(2) §15 — the Master controls tab**, named exactly that, first on every General page, carrying a canonical row set in a canonical order of which an addon ships **only the rows it has the state for**. A frameless addon omits exactly the four frame-only rows and **MUST NOT** invent a movable frame to fill the tab out; an addon whose frames are per-instance keeps the per-instance scale/alpha/lock on the instance's own page, because those are different settings from the addon-wide ones. *General visibility* is a four-value dropdown rather than a *show only in combat* boolean, since a boolean can only ever answer two of the four. **(3) §16 — the font, border and bar groups have fixed membership and a fixed row order**, contiguous, with anything extra appended after the block rather than interleaved into it, and **composed** from one declaration rather than typed out: nine hand-written copies of the same six rows is precisely the drift the shared library was extracted to end. A group over a **background** is not a bar group and does not grow a texture picker for a surface with no texture. **(4) §17 — the class-color companion, beside every color control.** The rule that was actually contested is *which* class, and it is settled here: the color resolves to the class of the unit the surface **describes** — the tracked unit's for a per-unit bar, cast bar or label, the player's for everything else — and because a stored path cannot be trusted to say which of the two a control is (a swatch under `units.<unit>.` may well draw the player's own spells), the intent is **declared on the row** and the declaration is what an audit reads. A color-mode dropdown carrying a `class` value satisfies the rule and **MUST NOT** be downgraded to a checkbox, which would delete the modes the third value names. **(5) §18 — one reorder control**, with the split stated in both directions: the library owns the handle, the bounded row box, the ghost, the insertion line, the index arithmetic and the boundary clamp, and the consumer owns everything inside the box and nothing about it. **The ripple, in four places.** **§8** now separates the two numbers a wrapped strip actually turns on, which the first draft of the table conflated in a section whose whole claim is that its values are exact: `TAB_H` (37) is the tab **button frame's** height, deliberately taller than the art it carries so the button's foot overlaps the content panel; the **row pitch** is the **unselected tab art's** measured height, is `≤ TAB_H`, and is what separates two wrapped rows. Both appear in one stated formula — `band = bannerHeight + (rowCount − 1) × pitch + TAB_H` — so §13's wrap-stability invariant is arithmetic an auditor can check against two inputs rather than a word to interpret. **§15's visibility dropdown is a stored-value type change** and says so: replacing a *show only in combat* boolean carries a `schemaVersion` bump and a migration step (`true` → `inCombat`, `false` → `always`) in the same change, because changing the type alone satisfies the rule's letter and silently loses a setting on every existing install. The tab **rename** is not a migration, and the two are named apart. **`AUDIT.md` goes from six checks to nine**, so every new MUST is decidable by an agent holding the playbook: **(g)** §14's chrome block (a page-wide control declared inside a `group` is in the scroll and is the finding; so is a second box around the band), **(h)** §13's wrap stability (the pitch's source in the vendored library, plus a suite case that would be green against nothing on a harness answering one height for every atlas), and **(i)** §13's secondary strip and the absent third level. Check (b) now asks for the visibility migration rather than only the tab name. And the **exemption is enumerated as two pages everywhere it is enumerated** — the AceConfig-drawn Profiles sub-page **and** the host-drawn landing page, whose `buildMain` body §5 mandates and which declares no `group` at all; the earlier one-page enumeration would have had an audit filing a MUST failure against every addon's landing page for rendering exactly as the standard requires.

  **Three rules are ratified here that were already unanimous across three independent implementations and written down in none:** a class color carries no alpha, so **the stored swatch's alpha survives the mode**; an unresolvable class **falls through to the stored swatch** rather than to gray, white or any hue chosen for the occasion; and the swatch is therefore **read under both modes and never disabled**, which makes `disabledIf` on a color row a statement to the player that is not true. **One deliberate reversal is recorded as one:** the shared reorder widget was written to own the handle, the ghost, the insertion line, the arithmetic and the clamp *and nothing else*, and it now also owns the row's bounded box — because "each row reads as a discrete draggable block" is a property of the **collection**, and a property of the collection cannot live in two consumers' private code. **What was deliberately not done:** the Profiles exemption is not a flag an addon can set, because an opt-out is a thing that gets set for the wrong reason and there is no way to see one in a test; a second level of tabs is permitted but a **third is not**; and §16 does not un-merge a tab that merges a background group with a border group on purpose — what it requires is a subsection heading saying where one stops and the next starts. Eight new anti-patterns, **#68–#75**, one per rule. Ripple: `options-ui-§7` gains the subsection heading and the one-heading-widget rule; `options-ui-§8` gains the tab-strip and reorder-row constant tables, without which §13's and §18's geometry rules would be guards nobody can measure; `options-ui-§14` is generalized from *the page banner* to *the chrome block* and forbids the redundant box drawn around it; the preamble's adoption-strength sentence stops naming a range (`§5 through §11`) it had already outgrown, which would otherwise have made every MUST in this release formally optional; plus `AUDIT.md` (six mechanical checks), `NEW_ADDON.md`, `NEW_ADDON_CONTEXT.md` — which was three releases stale and carried nothing about §13 or §14 at all, so §13–§18 are backfilled together — and `EXECUTIVE_SUMMARY.md`.

- **v2.27.0 (2026-08-06):** **The cheap half of the sweep was gated behind the expensive one, so people stopped sweeping.** `audit-review-history` has described a single command that discovers *and* interviews since the section existed — four discovery passes, then a decision per item, in one sitting. The discovery half is mechanical, safe and worth running across every repo at once; the triage half costs a human decision per item and can only be done attentively. Fused, **you could not find out what was hanging without committing to an interview about all of it**, and the observable result is a collection where a sweep is run when someone has an hour rather than when something changed. **So the command splits in two.** `/wow-addon:issue-audit` sweeps, reconciles each finding against the store by evidence hash, and files anything genuinely new as an open **`[untriaged]`** issue — **it never interviews and never changes code**. `/wow-addon:issue-triage` takes those `[untriaged]` issues, puts each to the maintainer with its verbatim evidence, and records the call on the issue — **it changes the issue store and nothing else**. The `[untriaged]` backlog between them stops being an unrecorded intention and becomes a countable quantity: the number of things found and not yet decided, visible in every listing. **Triage records rather than implements**, which is the one behavioral loss and is deliberate — accepting an item produces a `[deferred]` issue carrying the chosen approach, and the code change happens in an ordinary session against that issue, where it can be tested and reviewed like any other change rather than buried in the tail of a twenty-question interview. **An early stop is now free**: the queue already lives in the store, so stopping leaves the remainder `[untriaged]` and untouched, and nothing the user never saw is published to satisfy a run. **The four-value vocabulary is unchanged, and gains one absolute**: every issue **MUST** carry a `[status]` prefix at all times. The rationale is unconditional and is now stated **once**, here: a `#!/usr/bin/env bash` shebang followed by CRLF makes the kernel look for an interpreter literally named `bash\r` and every `case`/`in` line becomes a syntax error. **§4** — binary types **MUST** be marked `binary` rather than left to `text=auto`, whose detection is content-based: the live example is `realesrgan-x4plus-anime.param`, ncnn's plain-ASCII model definition sitting beside its own weights, which a CRLF pin would rewrite; `.bin` and `.param` appear in none of the nine existing files and `.tga` — the collection's **largest** binary population at 109 files — is missing from one of them. The list is deliberately ahead of the census, because a stale entry costs nothing and a missing one costs an asset. **§5 fixes one canonical file body per kind, verbatim, so a repo is diffed rather than read** — the two differ in the pin line, the paragraph declaring the repo's kind, and two word-level consequences of that; the `*.sh` block, the binary block and the renormalization recipe are byte-identical, so comparing a client-bound repo against a non-client one shows one decision instead of two documents. **§6 is the half that gets skipped**: attributes act on content only as it passes through git, so `git add --renormalize .` fixes the **INDEX** and does not rewrite bytes already on disk. A file written by `sed`, a Python generator, a WSL editor or a shell redirect stays LF in a CRLF repo, and git then emits `warning: in the working copy of 'X', LF will be replaced by CRLF the next time Git touches it` on **every** subsequent add — named verbatim in the section because it is the symptom a maintainer actually sees, and because being a warning rather than an error is precisely why it gets tuned out, leaving a repo with a policy, a clean `git status` and a tree that agrees with neither. It is cleared per file by `rm <path> && git checkout -- <path>`, verified with `file <path>`, and the change ends when `git add --renormalize .` stages nothing. **§7** makes it auditable, with the commands, and requires strays to be reported as **one** rolled-up finding carrying the command that produced the count. **Why none of this is cosmetic**, stated in the section rather than assumed: a CRLF shebang breaks the vendored runner for **everyone on every checkout** with an error that names the wrong thing; a whole-file ending flip buries a one-line change inside a diff of every line in the file, and at repo scale a **27,000-line** diff is not hard to review but impossible, so it is approved unread; and a vendored-copy `diff -r` gate goes red for a difference that is not a difference, training its readers to ignore the one gate that catches real drift. **Ripples.** `automated-tests-§2` stops presuming and starts **citing**: the carve-out is required unconditionally by `line-endings-§3` in **both** repo kinds, and *"Every other file in the collection is CRLF"* is deleted — it is now false of the two LF repos. - **v2.21.0 (2026-08-04):** **The tag is now gated on all four suites plus zero functions above CCN 15 — and the commit gate is deliberately left exactly as it was.** automated-tests-§3 said `perf` and `complexity` are "recorded, never gating", and v2.18.0/§10 said `MUST NOT gate commits` — both of which remain true and both of which are retained verbatim, because the argument behind them is an argument about **commit** gates specifically: a threshold on every commit is routed around with `--no-verify`, after which the gate protects nothing and the habit remains. A **release** has no such escape hatch. It is infrequent, deliberate, already the moment the addon is looked at whole (performance-§10), and the one point at which an unmeasured number stops being an internal note and becomes a claim made **to users**. So the two checkpoints now gate differently, on purpose: **commits** on lint + the harness (testing-§4, unchanged), **the tag** on `lint` pass — which already means zero warnings *and* zero errors, since `luacheck` exits non-zero on either — `tests` pass with zero failures, `perf` pass, `complexity` pass, and `suites.complexity.warnings == 0`. **Three constraints make this safe rather than a reversal.** First, **the runner does not change**: its exit code, its verdicts and its `gating: false` flags stay as specified, because the same vendored script is the commit gate and a threshold placed inside it would fire on every commit — the exact failure the old rule exists to prevent. The gate is evaluated by the **release command**, reading the `manifest.json` the run already writes. Second, **it runs before anything is edited**, so a refusal leaves the repo byte-identical to how it was found; a partial bump — TOC moved, tag not cut — is worse than a clean refusal, because the next attempt starts from a state nobody chose. Third, **a `skip` is not a pass**: automated-tests-§3 already forbids recording a missing tool as a pass, and a release claiming zero CCN > 15 on a run where `lizard` never executed is precisely that claim, so an unmeasured suite blocks the tag as **NOT EVALUATED** — visibly distinct from FAILED, and answered by installing the tool rather than by reading the silence as clean. One narrow exception survives: `perf` skipped because the addon ships **no `tests/perf.lua`** is nothing-to-run rather than nothing-measured, it passes, and it **MUST** be said plainly in the release notes instead of being allowed to read as measured. The gate also **MUST** report **every** failure rather than the first — a release blocked for a lint error that also has four failing tests and a CCN 62 function should be understood once, not across three rounds — naming each failing case and each function over 15 with its `file:line` and CCN, worst first, since the command has already read the bundle and a bare count only sends the reader back to it. **Minor bump, and the first rule in this standard that an addon can fail by standing still**: every addon currently carrying a CCN > 15 function is now blocked from releasing until it is fixed, which is the intent — the collection-wide sweep behind v2.20.0 found 86 of them, and a watch list that never converts into work is what v2.20.0's shelf-life rule already named as the failure. Nothing about day-to-day work changes: between commits the numbers stay advisory and argued with, which is what keeps them honest; at the tag they have to be true. Rippled into performance-§10's checkpoint bullet, automated-tests-§6, and the `bump-version` command, which now runs the battery as its Step 2 and refuses.

- **v2.20.0 (2026-08-04):** **The complexity report now has a rule for what to do about it, and the collection learned what a shared library must refuse to absorb.** v2.18.0 fixed the *measurement* — one path, one invocation, a release checkpoint, a watch list with dispositions — and it worked exactly as designed for two releases, at which point a collection-wide sweep found what the design had not anticipated: **86 functions over CCN 15 across nine repos**, every one carrying a standing "accepted" disposition, one addon holding 20. Nothing was broken. Each entry had been a reasonable call in isolation, and the rule as written renews an acceptance by doing nothing. The result is a list that costs maintenance and carries no signal, because the next genuinely alarming function would arrive into a list of eighty-six and be indistinguishable from them. So **a disposition now has a shelf life** (performance-§10, automated-tests-§4, anti-pattern #53): carried as accepted across **three consecutive release runs**, an entry is either fixed or converted to a tracked deviation with an ID and an owner, and the watch list points at the tracker rather than re-arguing it every release. A watch list too long to read in one pass is itself the finding — that is a backlog, and a backlog needs scheduling rather than another disposition line. **Reading the number is now specified, because in Lua it does not mean what it means elsewhere (performance-§10).** `lizard` counts every `and` and `or` short-circuit as a decision, so twelve `t.k = rec.k or D.k` defaulting lines are **CCN 13 with no visible branching at all**, and a stack of `if not x then return end` guards scores the same way. A high number in Lua usually means *this function defaults or guards a lot of fields*, not *this function has tangled control flow* — and the sweep's worst offender, a 40-branch `Sanitize`, was one flat list of `or` defaults that was never hard to read, while a 19-branch function with four nested loops was. The metric ranks them backwards, and an agent that does not know this reads the report inverted and "fixes" the wrong function. **New performance-§11 governs acting on a finding**, which the standard had left entirely open even while mandating the report: four permitted shapes (module-level table-driven dispatch; a named helper for a nameable block; a data table plus one loop; splitting a builder into N builders), a prohibition on the metric-gaming extraction that lowers CCN and raises confusion (anti-pattern #52 — the tell is the helper's **name**: `part2` and `doTheRest` were extracted for the number), a prohibition on the per-call allocation that a naive table-driven rewrite introduces on a per-frame path (#43's trade, made backwards), and a MUST NOT on changing behavior — including fixing a bug noticed in passing, because a behavior change hidden inside a large mechanical diff is unreviewable. **New testing-§13** supplies what makes any of it verifiable: a **characterization test written before the refactor and run against the unrefactored code**, because a test written afterwards asserts whatever the new code happens to do. The sweep found **16 of 86** warned functions with no coverage at all — by construction the ones a refactor is least safe to attempt and most likely to be aimed at, since complexity and untestedness have the same cause. **New savedvariables-§5 and anti-pattern #54** close a defect the refactor work would otherwise have introduced at scale: `t.k = stored.k or D.k` cannot distinguish *unset* from *set to `false`*, from `""`, or from an empty set, so the user turns an option off and it returns, clears a custom path and the shipped one comes back, deselects every entry in a set and the full selection reappears. It hides well because `0` is truthy in Lua — every numeric field a reader spot-checks behaves — and it puts the addon at odds with AceDB underneath it, whose defaults merge follows `nil`-ness and restores the `false` the addon's `or` layer then overrides. **And library-stack-§7 gains the counterweight to anti-pattern #47.** The standard said "don't hand-roll what LibKa0s provides" and said nothing about the opposite failure, which is harder to reverse because the additive-only rule makes a wrong abstraction surface the library keeps forever. Three bars now: 2+ consumers with the same **semantics** (not the same shape), **no per-consumer escape hatches** (those flags are the consumers' divergence re-encoded as configuration, and the library now owns a decision it cannot make), and a stable abstraction rather than a coincidence of today's code. Plus the rule that catches the most tempting mistake: **MUST NOT promote on frequency alone** — the collection's most-repeated shape is the optional-object guard at **400+ sites across nine repos**, and it must stay inline, because a `CallIf` helper turns a compile-time call into a stringly-typed lookup invisible to `grep` and `luacheck` and erases the three distinct reasons those guards exist. The worked rejection is the schema-migration runner (anti-pattern #55), nominated from eight repos holding **five incompatible variants** that disagree on who stamps `schemaVersion`, when, and whether a failed step still stamps — needing five escape hatches to own an eight-line loop, with silent SavedVariables corruption as the downside. **Duplication was the cheaper answer**, and the complexity win it was nominated for was available locally anyway. The underlying disagreement is recorded in `open-evolutions` as a ruling the standard still owes, together with the AceDB trap that makes it hard: the defaults merge backfills `schemaVersion` to current the moment `db.global` is first read, so the stamp alone cannot tell a fresh install from a legacy account. **Minor bump.** Nothing an addon ships becomes non-compliant on adoption: §11 and testing-§13 constrain a refactor only once you undertake one, and the disposition shelf life first bites at an addon's third release run after adoption. What changes immediately is that `or`-defaulting a falsy-meaningful field is now a named anti-pattern rather than a style preference. Drawn from a nine-repo `feat/fix-ccn` sweep that read all 86 warned functions in full before proposing a single edit — which is also how the `and`/`or` tax and the five-variant migration divergence were found, neither being visible from any one repo.

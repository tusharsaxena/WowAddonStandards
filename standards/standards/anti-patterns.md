> Part of the **[Ka0s WoW Addon Standard](../STANDARDS.md)** — the split standard. Cross-references use the `filename-§N` form (see the index's section map).

## Anti-patterns (forbidden)

For quick reference, the rules above as a do-not list:

1. `_G[addonName] = {}` (global namespace) — use private `NS`.
2. AceLocale strict mode — use metatable fallback.
3. Hand-rolled options framework — **consume `LibKa0s-Options-1.0`**, which is Settings + AceGUI with the shell, the five widget makers and the flow engine already in it (options-ui-§1); #47 is the general form.
4. AceConfig for non-Profiles content — use raw AceGUI.
5. `SLASH_*` direct registration — use AceConsole.
6. `if cmd == "x" then elseif ...` slash dispatcher — use schema + COMMANDS table.
7. `.pkgmeta` `externals:` for libraries — vendor and commit all libs instead (library-stack-§3).
8. Forking Ace libs — use `RegisterWidgetType` extension instead. That is a sanction for a **new** widget name the addon defines; re-registering a name it did not define writes into a process-global table and is the library's call to make, not an addon's (#76, library-stack-§9).
9. `if WOW_PROJECT_ID == ...` game-flavor branching — Retail only; route any Retail-patch check through Compat (compat).
10. Direct calls to deprecated APIs — route through Compat.
11. `:Hide()` on Blizzard frames you replace — reparent to hidden parent.
12. Replacing `AddMessage` — override globals or use AddMessageEventFilter.
13. Hard `## Dependencies:` (use OptionalDeps + soft fallback).
14. `## X-License: All Rights Reserved` — must be MIT.
15. Multi-flavor / Classic support (comma Interface lists, per-flavor TOCs, `_Classic` data splits, `enable-toc-creation` fan-out) — Retail only, single Interface line (toc-file-§3).
16. Files >1500 LOC — peel. The cap reaches every authored `.lua` in the repo, `tests/` included; `libs/`, `tests/_kit/` and generated non-shipping data are the carve-outs, and an over-cap file that is neither peeled, issue-tracked nor register-recorded is what this entry is actually pointing at (layout-§1).
17. Multiple senders for the same bus message.
18. Debug output to the chat frame when the addon has a main window — use the on-screen debug console (debug-logging).
19. Cross-module direct table access — use the bus.
20. User-supplied Lua execution — banned at the standard level (no Ka0s addon needs it).
21. Creating a feature/topic branch without an explicit request — work trunk-based (versioning-git).
22. Deferring settings-**category** registration until first `/config`/panel-open — register the category eagerly at load; only the body is lazy (options-ui-§1, options-ui-§9).
23. Committing with red `lua tests/run.lua` or non-clean `luacheck .` — the commit gate is green tests + clean lint (testing).
24. No `tests/` harness, or a logic change with no covering test — TDD is mandatory (testing).
25. Loose files directly in `media/` — use typed subfolders (layout-§3).
26. Full agent brief in the root `CLAUDE.md` — root `CLAUDE.md` is a stub; the brief lives in `docs/` (documentation).
27. A checked-in `TODO.md` in a **released** addon — track the backlog in GitHub issues; a `TODO.md` is allowed only in an unreleased, in-development addon during its development phase (documentation-§4).
28. Non-canonical `README.md` section order, or a TOC that departs from the required field order / file-listing structure — follow documentation-§1 and toc-file-§1/toc-file-§5.
29. Hard-depending on an addon suite or standalone addon (ElvUI/EllesmereUI/DBM/WeakAuras/…), or reading its media/API/frames/SavedVariables — addons are fully self-contained; suite integration is optional, presence-guarded, and degrades gracefully (library-stack-§6).
30. Hiding the options-panel scrollbar on short pages (bar shown only when content overflows) — the body `ScrollFrame` keeps its bar always shown and inert so body width is identical across subcategories (options-ui-§10).
31. A 50/50 paired action button left at `SetRelativeWidth(0.5)` — cell-filling buttons inset to `BUTTON_PAIR_REL` (0.492) so the right button clears the `ScrollFrame` clip (options-ui-§6, options-ui-§8, options-ui-§10).
32. Two receivers of the same bus message registering on the **shared** bus object (`NS.bus`/`NS.addon` as `self`) — CallbackHandler keys callbacks by `(message, target)`, so the later registrant silently clobbers the earlier (last-registrant-wins, no error, masked by `/reload`); each receiver MUST own a distinct AceEvent target — an AceAddon module `self`, or a private `NS.NewBusTarget()` embed (architecture-§4).
33. A bus test mock with no-op `RegisterMessage`/`SendMessage` — it can't catch same-target receiver clobbering; the mock MUST key by target and fan `SendMessage` out to all targets (architecture-§4, testing).
34. Missing the standards reference in **project memory and context** — a `CLAUDE.md` with no `## Standards compliance (read first)` section, so an agent loads the repo's working context without ever being told the addon is built to a standard or how to behave when a change would deviate from it (documentation-§6).
35. Feeding a combat-protected "secret" value (unit absorb/health totals, threat, …) into `table.concat`/`string.format`/`print`, or detecting one with a `..`-based probe — secrets **propagate silently through `..`** and only raise in `table.concat`, so a `..` probe passes them through; route every chat/debug arg through the shared secret-safe stringifier (events-frames-taint-§8).
36. Embedding AceConsole-3.0 into the **same table** that exposes a same-named custom printer — `AceAddon:NewAddon(NS, …, "AceConsole-3.0")` stamps AceConsole's `:Print` mixin directly onto `NS`, **silently overwriting** a custom `NS.Print` defined earlier (e.g. in an already-loaded `Util`). Every `print(msg)` call site then hits AceConsole's `Print`, which — called as `NS.Print(msg)` with the message as `self` — renders `|cff33ff99<msg>|r:` (green text, **trailing colon, NO cyan tag**), violating the mandated prefix (slash-commands-§4) with no error, masked by `/reload`, and invisible to any headless test whose AceAddon mock doesn't reproduce the embed. The **MUST** rule and its two fixes (name the printer `NS.Util.print`, or reclaim `NS.Print = NS.Util.print` right after `NewAddon`) — plus the mock-fidelity requirement (same as #33) — are in **architecture-§2**.
37. Matching game data against a **localized display string** — comparing a spell/aura name, item name, class/race name, zone name, unit/NPC name, or combat-log/error text against a hardcoded English literal (or passing a localized **name** to an ID-returning API, e.g. `C_Spell.GetSpellInfo("Power Word: Shield")`). The game returns these already translated, so the branch is true only on an enUS client and dead on every deDE/frFR/ruRU/koKR/zhCN/… client — a bug invisible to an English-speaking author and masked by never reproducing locally. **MUST** key on the stable ID or non-localized token instead: `spellID`, `itemID`, the `classFile`/race/faction token (2nd return of `UnitClass`/`UnitRace`/`UnitFactionGroup`), `creatureID` from `UnitGUID`, `uiMapID`/`instanceID`, an `Enum.*` member; or, when Blizzard text truly must be matched, the localized **GlobalString** constant (`_G.ERR_*`, `SPELL_FAILED_*`) — never its English value. Uppercase tokens (`"PRIEST"`), unit tokens (`"player"`), and event names are the *correct* form, not this anti-pattern (localization-§4).
38. An addon-authored `embeds.xml` (or any aggregate `.xml` the TOC loads as a single line) that pulls in the vendored libraries — list each library **directly** in the TOC's `# Libraries` section instead (one entry per library, its `.lua` or the library's own packaged `.xml`, in dependency order), so the load order lives in the one TOC every Ka0s addon reads identically rather than being hidden in a second file (toc-file-§4).
39. Refreshing an options panel by re-running **every** rendered sub-page's full renderer on each mutation — a complete AceGUI teardown + rebuild of all N visited subcategories per checkbox toggle / slash `set` / list edit, which turns one interaction into O(N) page rebuilds and stalls the client for a visible beat (≈0.5s once ~15 sub-pages have been opened). The Blizzard Settings window shows one subcategory at a time: refresh scalar widgets **in place** via per-widget updater closures, and scope any structural rebuild to the **on-screen** subcategory (`ctx.panel:IsShown()`), marking hidden panels dirty for a lazy rebuild on next `OnShow` (options-ui-§11). Also a raw `UIPanelButtonTemplate` header/Defaults button parented onto the Settings canvas (inherits the canvas red skin) — build header buttons as AceGUI `Button`s (options-ui-§5).
40. **Retired at v2.42.0.** This required a `## What's new` highlights section in every README and forbade a stale one. `documentation-§1` no longer carries that section: it duplicated the top `## Version History` row by construction, and a MUST whose content is a copy of another MUST can only ever be in sync or in breach. The number is kept rather than reused, so every existing citation of #40 still resolves to what it meant.
41. A debug console whose log is a **wheel-only `ScrollingMessageFrame`** — no scrollbar and no line counter — so the developer can't see scroll position or how full the 1500-line buffer is (debug-logging-§11 makes both a **MUST**). Or, worse, one that drives the log with the **old C getters `GetNumLinesDisplayed()` / `GetCurrentScroll()`**, which are **`nil`** on retail's Lua `ScrollingMessageFrameMixin` and raise *"attempt to call a nil value"* the first time the console opens — the mixin's scroll API is `GetMaxScrollRange()` / `GetScrollOffset()` / `SetScrollOffset()` (offset `0` = newest/bottom). Guard method presence before calling so a headless mock stays a no-op, and run the initial scrollbar/counter sync **last** in the window build so a frame-API error can't abort the header/ESC wiring (debug-logging-§11).
42. Building the options header's **Defaults button (or any header/action button) while registering the settings category** — i.e. inside `OnInitialize`/`buildHeader` rather than in the panel's first `OnShow`. AceGUI is a **shared** library and UI skins restyle its widgets by hooking `RegisterAsWidget`, so a widget created *during load* — before later-loading addons install those hooks — keeps Blizzard's stock `UI-Panel-Button-Up` art (the **red stone button**) for the session, while everything created afterwards comes out skinned. The result is a button that renders red in one addon and correct in its siblings **from identical code**, decided purely by folder load order, and that flips when an addon is renamed or a skin is added. Record the intent at registration (`panel.wantsDefaultsButton`), park the callback (`panel.defaultsOnClick`), and build the widget on first `OnShow` — the same lazy rule the panel body already follows (options-ui-§5/§1). The tell is in the live object's **region list**, not the source: bare 5-region `130828` = unskinned (options-ui-§5).
43. **Ungated instrumentation in a hot path** — a timing bracket, counter, label, or log line on a per-frame / per-event path that does work when capture is **off**: calling `debugprofilestop()` unconditionally, building a bucket key or format string "ready for when capture starts", allocating a table per call, or reaching the probe through an `NS` lookup instead of a load-time upvalue. Measurement you can't turn off is a permanent tax levied to answer a question nobody is asking right now, and it is paid on exactly the paths that matter. The mandated form is `local t0 = Perf.on and debugprofilestop()` … `if t0 then Perf.Note(key, debugprofilestop() - t0) end` — one upvalue read, one field read, one boolean test when off — with the offline zero-overhead scenario as **required evidence** rather than a comment claiming it (performance-§2, performance-§9).
44. **A shared frame used for measurement** — one `OnUpdate` sampler (or any frame) created by a library and reused across every host addon. WoW's Addon Profiler bills a shared frame's CPU to whichever addon **created** it, so a shared sampler makes the measuring instrument corrupt the very attribution it exists to fix: the first-alphabetical host absorbs its siblings' cost and every reading is wrong in a way that looks plausible. Every frame a shared harness creates **MUST** belong to the calling host, created inside its per-host constructor (performance-§1). The same trap explains why a capture's two arms **MUST NOT** be produced by enabling and disabling addons — that moves frame ownership too (performance-§7). This is also why the test suite for such a library **MUST** be able to fail when a frame is hoisted to file scope; a suite that passes either way is not testing the invariant.
45. **A vendored Ka0s-owned library that has drifted from its source repo** — a `libs/<Lib>/` copy that is not byte-identical to the library repo's ship folder, whether from a local hand-patch or from a library change that never got its **re-vendor commit** in this addon. Uniquely silent: the library's own suite passes against the library, the addon's suite passes against the stale copy that still works, and **both repos stay green** while the copies diverge — so nothing about "the tests are green" will tell you. Compounding it, LibStub picks a winner by comparing **minor** integers, so a library change whose file minor was never bumped does not reach any host already carrying the old copy at all. `diff -r <LibRepo>/<Lib> <Addon>/libs/<Lib>` **MUST** be empty, a lib change **MUST** be followed by a re-vendor commit in every consumer, and every released change to a lib file **MUST** bump that file's minor (library-stack-§7, versioning-git).
46. **British spelling in authored English text** — `colour`/`grey`/`behaviour`/`centre`/`cancelled`/`-ise`/`-isation` in a locale key or `enUS` value, a chat or options string, a code comment, an identifier, or README/`docs/` prose. US English is the collection's source dialect (localization-§5): WoW's own API is US-spelled (`SetTextColor`, `GRAY_FONT_COLOR`), so a British-spelled identifier sits one letter from the Blizzard symbol next to it and a `grep -r color` silently misses half its call sites, while a mixed-dialect collection cannot be swept with one pattern. Worst in a **locale key**, where the key *is* the English string: fixing it changes the key, so every `locales/*.lua` file and call site MUST move in the same change or the metatable falls through and renders the raw key on that client (localization-§1/§2). Blizzard/library symbols, quoted external text, published proper nouns, and a deliberate `locales/enGB.lua` translation are the sanctioned exceptions — reproduce those verbatim. The handful of spellings named above are illustrative; the canonical machine-readable pair of lists — `BRITISH` substrings and the `ALLOWED` US words that contain one — is published in localization-§5, and a mechanical gate **MUST** take both of them **whole**. A gate carrying a private subset is the second anti-pattern stacked on the first: it reads as coverage and provides none (#56, testing-§12).
47. **Hand-rolling a debug console, an options toolkit, a slash dispatcher, or a headless test harness that a LibKa0s module already provides** — a private `ScrollingMessageFrame` log and copy window, a per-addon set of widget makers and a two-column flow engine, an addon-local dispatcher/help renderer/value parser, or a hand-written `tests/` framework — and, the same defect one step further along, **forking the vendored copy** to "just fix this one thing" here (library-stack-§5). Every one of these *was* per-addon code in this collection, which is precisely how the collection learned the rule: one formatter existed seven times over, each subtly different, so a fix landed in one of them and in none of the others — and no repo went red to say so, because each addon's suite tested its own copy and passed. Drift of this kind is not found by testing; it is found months later by a user reporting that two Ka0s addons format the same line differently. Consuming is a descriptor plus a degradation stub in the addon's own setup file; a fork is a maintenance burden nobody agreed to carry and that nothing will remind you of. Vendor the whole `LibKa0s/` folder, build the instance from a descriptor, and push anything genuinely missing back into the library as an **additive** descriptor field (library-stack-§7) so every consumer gets it, rather than patching it locally (debug-logging, options-ui, slash-commands, testing). Two things are **not** this. A library-absent **degradation stub** of a shape options-ui-§1 names runs only while the major is absent, where the copy this entry names runs instead of the library: the **runtime-completing** stub for a major whose own API document prescribes one (today `LibKa0s-Schema-1.0` alone), and `LibKa0s-Compat-1.0`'s **guard arm**, are deliberate duplications, commented at the host copy and citing the major's API document, and Compat's **reader arm** and `LibKa0s-Bus-1.0`'s **untracked-target stub** copy nothing of the library. Nor is a host's own copy of a shape `LibKa0s-Compat-1.0`, `LibKa0s-Bus-1.0` or `LibKa0s-Schema-1.0` now carries, written before it adopts the major. That holds from v2.64.0 until a later version of this standard makes adopting them a requirement (library-stack-§7).
48. **Partial or per-module re-vendoring of a multi-file LibStub major** — copying `Perf.lua` without `Core.lua`, or a shell file (`Options.lua`, `Perf.lua`, `Widgets.lua`) without the attach files that complete it (`OptionsWidgets.lua`, `OptionsTabs.lua`, `OptionsCompose.lua`, `OptionsScroll.lua`; `PerfPanel.lua`; `WidgetsDragHandle.lua`), instead of copying the whole `LibKa0s/` ship folder and TOC-listing its packaged `LibKa0s.xml`. It produces two different failures, and the second is the one that costs a debugging session. Fourteen of LibKa0s's fifteen majors — every one except `Core` itself — `return` **before** `LibStub:NewLibrary` when Core is missing or older than their floor, so the major is never registered at all: `LibStub(major, true)` yields nil, the module is **absent** rather than half-wired, and the host silently runs its degradation stub — the addon loads and works, badly, with no error to explain the missing console or settings panel. But a major whose **shell** arrives while its attach file does not registers normally and `:New` **succeeds**, handing back an instance whose attached members are simply not there; that failure surfaces at **call** time — a panel build, a report render, a page the user opens next week — as *"attempt to call field '…' (a nil value)"*, far from the vendoring commit that caused it. One rule cures both: the library repo's ship folder is the unit of vendoring, `diff -r <LibRepo>/LibKa0s <Addon>/libs/LibKa0s` is empty, and a multi-file major's files are paired by **version**, not merely by presence (library-stack-§7).

49. Shipping the **scaffolding pack** in the repo — a `docs/agent-context.md` (under that name or any other) holding `NEW_ADDON_CONTEXT.md`'s kickstart walkthrough, starter tree, starter snippets or "definition of done for v0.1.0". It is a starter, every question it answers is answered the moment the addon exists, and it is loaded as **working context** — so a copy that still shows how to hand-write a console, a dispatcher or a harness will get one hand-written in an addon that replaced all three (#47). No gate can see it: no test covers a doc and lint does not read prose. Fetch it at runtime into a temp directory; never write it into the addon (documentation-§3).

50. **An undocumented toolchain** — a repo whose install requirements exist only as a `docs/testing.md` aside, a `## OptionalDeps` line and a script's `import`, with no root `DEPENDENCIES.md` (documentation-§7); or one whose `DEPENDENCIES.md` has drifted from what the repo actually needs. The failure is silent in the worst possible place: on the **maintainer's** machine everything is already installed, so nothing is ever missing and no gate can notice — the list is only wrong for the person who does not yet have it working, and they cannot tell an incomplete list from their own mistake. It is compounded by instructions that *look* right and are not: `pip install lizard` on Ubuntu 24.04 fails on PEP 668's `EXTERNALLY-MANAGED` marker, and a reader who hits that error concludes the tool is unavailable rather than that the document is stale. Name every dependency with the evidence for it, split runtime from development from release-only, give the WSL2/Ubuntu command that actually works plus a one-line verification, and refresh it in the change that adds the import — not at the next audit (documentation-§7, documentation-§5).

51. **A complexity report that is regenerated but never read** — `docs/complexity.md` overwritten at release with a fresh table and no watch list, so a function that went from CCN 9 to CCN 24 lands in the commit as a changed number nobody compared. The report's entire value is the **diff between releases**; a regeneration that yields no disposition for what newly crossed a threshold has performed the ritual and skipped the point, while leaving an artifact that reads as though the addon's complexity is being managed. Two cousins are as bad: **regenerating with a locally "improved" invocation** (extra flags, a narrowed path, re-tuned thresholds), which silently makes the new report incomparable to every earlier one — the single property the fixed command in performance-§10 exists to protect — and **hand-editing the numbers**, which is worse than an absent report because it reads as measured. Keep the invocation verbatim, keep the one overwritten path so git carries the trend, write "None." when the watch list is empty, and when `lizard` is absent leave the previous report standing with its own date rather than deleting it (performance-§10).
52. **Refactoring to move a complexity number rather than to make the code readable** — extracting a function's body wholesale into one helper so the wrapper scores well (`part2`, `doTheRest`, `handleEverythingElse`), respelling `x = a or b` as `if a ~= nil then x = a else x = b end` (the identical decision count in three times the lines), or pushing an `if`/`elseif` chain into a table of closures **built inside the function**, which trades branches for a per-call allocation and is strictly worse on any path that runs per frame or per row (#43). All three lower the reported CCN and none of them lowers the complexity, which is the point at which the report has started causing the harm it was adopted to prevent. The tell is the helper's **name**: if it does not describe a thing a reader would recognize, the extraction was for the metric. The permitted shapes — module-level table-driven dispatch, a named helper for a nameable block, a data table plus one loop, or splitting a builder into N builders — are in performance-§11, along with the rule that the refactor **MUST NOT** change behavior or drop a comment that records why.
53. **A complexity watch list where everything is "accepted"** — dispositions written once and renewed by default, until the list is a permanent inventory rather than a decision record. It is self-concealing: every entry was a reasonable call **in isolation**, and the list only fails collectively, at the moment a genuinely alarming function arrives into a list of eighty-six and cannot be distinguished from them. A 2026-08 sweep of the collection found exactly that — **86 functions over CCN 15 across nine repos**, one addon carrying 20 — all of them individually justified and none of them ever scheduled. The rule is a shelf life, not a threshold: an entry carried as accepted across **three consecutive release runs** is either fixed or converted into a tracked deviation with an ID and an owner, after which the watch list points at the tracker instead of re-arguing it every release (performance-§10, automated-tests-§4).
54. **`or`-defaulting a stored value whose falsy state is a user choice** — `t.k = stored.k or D.k` applied across a settings table, which cannot distinguish *unset* from *set to `false`*, from `""`, or from an empty set. The user turns an option off and it comes back on; they clear a custom path and the shipped one returns; they deselect every entry in a set and the full default selection reappears. It hides well because `0` is truthy in Lua, so every numeric field a reader spot-checks behaves correctly and only the booleans and empty collections are wrong. It also puts the addon at odds with the library beneath it: AceDB's own defaults merge follows `nil`-ness, so AceDB restores the stored `false` and the addon's `or` layer overrides it on the next read. Test absence with **`== nil`**, and comment the fields where empty is a deliberate choice **at the point of defaulting**, because the next mechanical sweep over that table is what undoes it (savedvariables-§5). Especially easy to introduce while refactoring for complexity, where a careful `== nil` ladder is exactly what a compact `or` table looks like an improvement on (performance-§11).
55. **Promoting a shape into a shared lib because it is repeated, rather than because it is shared** — a helper whose consumers need a behavior flag each (at which point the library owns a decision it cannot make, and the flags are the consumers' divergence re-encoded as configuration), or one promoted on raw frequency where the shape carries almost no meaning. The collection's most-repeated shape is the optional-object guard at **400+ sites across nine repos**, and promoting it would be a mistake: `CallIf(obj, "method", ...)` turns a compile-time call into a stringly-typed lookup invisible to `grep` and to `luacheck`, and erases the three distinct reasons those guards exist (an API absent on this client build, an optional module not yet loaded, a headless mock with holes). The sharper case is a shape whose consumers disagree about **correctness**: a schema-migration runner was nominated from eight repos holding five incompatible variants — disagreeing on who stamps the version, when, and whether a failed step still stamps — and needed five escape hatches to own an eight-line loop, with silent SavedVariables corruption as the downside. **Duplication was the cheaper answer.** Under the additive-only rule a wrong shared abstraction is surface the library keeps forever, which is why this failure is harder to reverse than the duplication it was meant to cure (library-stack-§7; the opposite failure, hand-rolling what a module already provides, is #47).
56. **A degradation stub whose member set has drifted from the host's call sites** — the addon's own fallback for an absent LibKa0s module (library-stack-§7, #48), missing a member the host calls, or refusing verbs that never went to the library at all. It is the sharpest failure class in this collection and it is invisible to **every** green suite, for one structural reason: no suite loads the addon degraded, so the stub is never the object under test. The addon loads, lints and passes; the defect surfaces at **call** time, on the one path a user reaches next week. Two reproduced shapes. **(1) A bare call on a nil member, after the write already landed** — the settings value is committed, *then* the stub raises, so the SavedVariables state and the error are out of step and a `/reload` "fixes" it into a session-long error loop nobody can reproduce from the report. **(2) A stub that blacks out verbs that never went to the library** — one addon's degraded slash layer refused all 17 of its verbs including the 11 that were always host-owned, against slash-commands-§1's plain rule that the host verbs keep working. Two things make it hard to see by reading: the options stub's **load-completing** exception (options-ui-§1) is about what a member *does*, not about which members *exist*, and both reproduced failures hid behind it; and a hand-written parity test is built from the same member list it then asserts, so it agrees with itself and stays green. The gate is testing-§8's **stub-surface parity case** — the grep-derived member list with the grep named in the comment, asserted on **both** arms, with the degraded arm produced by feeding the loader a deliberately partial file list rather than by hand-stubbing the member under test (testing-§8, performance-§1, options-ui-§1, slash-commands-§1).

57. **A repo with no `.gitattributes`, or one carrying only the `*.sh` carve-out** — so what lands on disk at every checkout is decided by whichever `core.autocrlf` / `core.eol` the contributor's git happens to hold, and two people produce byte-different working trees from the same commit while both do everything right. The measured collection is the evidence, and it is dated. The sweep that produced this entry found **two repos with no file at all** — `WowAddonStandards` and `wow-addon`, the repo that publishes this standard and the plugin whose own `scripts/normalize-eol.sh` the kernel refuses to run if it ever arrives CRLF — and **that gap has since been closed**: both now carry the non-client canonical body of `line-endings-§5`, byte-for-byte. Standing beside them at the same sweep: **one repo with the carve-out and no pin** (`PanelMaster`, five lines, **111 of its 185 tracked text files** LF against the collection's intent), and **eight hand-maintained copies of one policy** in files of **34, 36, 34, 35, 22, 31, 68 and 30 lines**. The near-miss is the worst of the three, because a `.gitattributes` that lists exceptions reads in review as a repo that has been handled. **No gate sees any of it**: `luacheck` does not read bytes, no test loads the working-tree encoding, and the tree looks correct on the machine that produced it — the file is only ever wrong for someone else, later. The cousin failure is adopting the file and stopping there: `git add --renormalize .` fixes the **index** and never the working tree, so `warning: in the working copy of 'X', LF will be replaced by CRLF the next time Git touches it` is emitted on every subsequent add and, being a warning, gets tuned out. Carry the canonical body for the repo's kind, keep `*.sh text eol=lf` in both kinds, mark the binaries, and finish the adoption with a `git add --renormalize .` that stages nothing (`line-endings-§1`/`§2`/`§3`/`§4`/`§6`).

58. **A vendored-library inventory in the player-facing README** — a `## Libraries`, `## Bundled libraries`, `## Libraries and credits`, `## Credits and libraries` or `## Credits and bundled libraries` section listing Ace3, LibSharedMedia, LibDataBroker, LibDBIcon and the rest, or the same roll-call written into the intro paragraph where no heading gives it away. It reads as thoroughness and is addressed to nobody: the libraries ship **inside** the addon, so the player it is written for has nothing to install, nothing to choose and no decision the list informs — while the contributor who does need it reads `DEPENDENCIES.md` and `docs/ARCHITECTURE.md`, which name every dependency with the evidence for it. So the README copy is a third statement of a fact whose two real homes are already mandated, on the one surface no gate has ever checked, and it goes stale in the specific way that is hardest to notice: a library added or dropped changes the TOC, the `libs/` tree and `DEPENDENCIES.md`, all of which something reads, and the README paragraph that nothing reads keeps its old answer. Delete the section; if it also carried **genuinely external** credit — third-party artwork, a font, a sound pack, another author's work — keep those lines alone as a plain `## Credits` and delete every link and cross-reference that pointed at the old heading (documentation-§1 item 12 and the no-inventory rule, documentation-§7).

59. **The LibKa0s provenance line left in `README.md`** — *"Bundles [LibKa0s](…) vX.Y.Z (MIT)."* sitting where it has sat since the library was first vendored, in a repo that has re-vendored `tests/_kit/` at **testkit revision 9 or later**. It is the sharper half of #58, because this line is not merely unread: it is the **input** to the consumer-side vendored-payload gate (testing-§11), which since LibKa0s **v1.8.1** reads it out of root `CLAUDE.md` and has **no fallback** to `README.md`. A repo that copies the new kit and leaves the line where it was reads to the gate as carrying **no provenance line at all** and fails the case, naming `CLAUDE.md`. The absence of a fallback is the design, not an oversight — two lines that can disagree, with a gate silently preferring one of them, is the same drift the gate exists to catch. The migration is one commit and it is the same commit as the re-vendor: move the line into `CLAUDE.md` naming the tag the payload came from, and regenerate `docs/test-cases.md`, since the case's own name changed with the file it reads (documentation-§2 item 6, library-stack-§7, testing-§11, testing-§5).

60. **A surviving `docs/pending/LEDGER.md`** — the tracked markdown table that used to hold issue-audit decisions, left in the repo after the store moved to **GitHub issues on the addon's own repo** (`audit-review-history`). It is not a harmless leftover file: it is a **second** answer to "what did we decide about this item", and it is the stale one, because the interview that produces decisions now writes issues and never touches it. A maintainer reading the ledger sees deferrals that were closed months ago and misses the ones filed since; an agent grepping for prior decisions finds it first, because it is in the working tree and the issues are not. Retire it in one commit: every `deferred` row becomes an **open** issue labeled `state:triaged` (and a `severity:` label), `done` and `wont-do` rows migrate nowhere — they are terminal, and the deletion commit preserves them in git history — and the file and its `docs/pending/` directory are deleted, along with the `## Documentation map` row that named the directory (documentation-§3).

61. **A committed perf capture with no reading beside it** — a record in `docs/perf-analysis/` whose bundle has a `dump.json` and no `ANALYSIS.md`, or a bundle whose `ANALYSIS.md` restates the report's rows without saying what they mean. `performance-§8` has always said an interpretation without its record is an assertion; this is the mirror defect, and it is the more common one because taking a capture is five minutes and reading one is an hour. An unread record is not neutral — it **reads as evidence**. The next person to open the store finds a directory of measurements and reasonably concludes the question was settled, when in fact nobody ever looked at the numbers; a capture whose buckets show a hot path nobody noticed is worse than no capture at all, because its presence is what stops anyone taking another. The related shape is a capture read up **somewhere else** — an investigation, an issue comment, a commit message — leaving the record and its reading joined by a link that outlives neither. Write the reading into the bundle, following the root `PERF_ANALYSIS.md` prompt, and let `docs/investigations/` cite it rather than replace it.

62. **A `[status]` prefix left on an issue title** — `[triaged] Autosize a panel to a target frame`, sitting in a repo whose store has moved to `state:` and `severity:` **labels** (`audit-review-history`). It is the same defect as #60 one layer in: a **second** answer to "what is the status of this item", and the stale one, because every command that writes the store now writes labels and none of them writes the prefix. The two disagree the first time an item is triaged, and the prefix is the copy a human reads first, because it is what a bare `gh issue list` prints. It also costs the title the width its actual content needs, and it makes the status unfilterable — the whole reason to move it to a label was that `--label` is a query and a leading substring is not. Repair is one edit per issue: strip the prefix, add the `state:` label it named and a `severity:` label judged from the body, and change nothing else about the title text — an issue whose prefix left it reading `ARTWORK-10:` keeps that text, because a migration is the wrong place to rewrite somebody's words. The related shape is a **severity word in the title** (`[HIGH] …`), which is the same mistake against the second label. An issue carrying **no** `state:` label at all is not this anti-pattern — it is the ordinary stray the commands repair on sight.

63. **A private copy of shared media, or a one-off mark where the catalog has one** — a `media/icons/` folder in an addon holding icons the vendored payload already ships, a second copy of JetBrains Mono under `media/fonts/`, a bar texture drawn locally, or — the commonest shape — a control drawing a **word**, a Unicode glyph or a Blizzard atlas where `LibKa0s-Media-1.0` carries the mark for it. The payload is whole-folder, so the addon is **already shipping the art** either way: the private copy costs bytes twice, doubles the licenses to track and the provenance stories to keep, and produces the failure it was never trying to produce — two Ka0s addons whose title bars stop matching the first time one copy is regenerated and the other is not. It hides because each addon looks *internally* consistent, and the inconsistency only exists between windows a user opens side by side. The tell is a `media/` folder that two addons in the collection could swap without either noticing, or a header strip where one control is a texture and its neighbor is a `×`. Draw from the catalog; a mark it lacks is added **upstream**, in the same style, by the generator that produced the rest — art separated from its generator is a folder of binaries nobody can regenerate, relicense or resize (library-stack-§8, layout-§3).

64. **A forwarder that does not carry an argument its target has grown** — a one-line passthrough (`function lib.F(a, b) return other.F(a, b) end`) left at two parameters after the function it wraps took a third. It is the failure mode of the indirection that exists for a good reason: a forwarder is what lets a dependency upgraded underneath an unchanged wrapper still be the one that runs, and the same indirection silently truncates the call. **Nothing reports it.** The target sees fewer arguments, defaults the missing one and does something perfectly reasonable — no error, no warning, no log line — so every suite stays green while the feature the argument carries is half-applied. The measured instance: a debug console shipped with its copy and clear controls drawing the shared icon set beside a close button still drawing a multiplication sign, because those two were built directly and the third went through a two-argument forwarder; the only symptom was the screenshot. Test the **argument**, not the appearance — assert that the wrapper passes what it was given through to its target — because appearance is exactly what an out-of-game suite cannot see. Cousins: an adapter that drops a new descriptor field, and a wrapper whose `...` was replaced by named parameters during a "clarity" refactor.

65. **A call site that omits the argument its factory has grown** — `MakeCloseButton(frame, hide)` written against a function whose third parameter is the addon's own **folder** name, the one thing that decides whether the control draws the shared `close` mark or falls back to a multiplication sign. It is #64's sibling and the more common of the two: #64 is one forwarder inside a library, this is every place an addon builds a window. Reaching the factory through a module's re-export (`NS.DebugLog.MakeCloseButton`) does not help — it is the same three-argument function, and going through the console does not supply the name. **Nothing reports it**: the factory receives no name, builds no texture path, and draws a perfectly good button; a texture path that is never built draws nothing and raises nothing, so lint is clean, the suite is green, and the only witness is a person with two windows open. The measured instance is a **perf panel drawing `×` two inches from a debug console drawing the mark**, in an addon that had already adopted the icon set everywhere else — found by a screenshot, one release after the same defect in the library beneath it. The cure is structural rather than vigilant: **one wrapper per addon**, defined in the `LibKa0s-Core-1.0` setup file where the folder name is already in scope, and every close control built through it, so `grep -rn 'MakeCloseButton(' --include='*.lua' | grep -v '/libs/'` returns the wrapper and its callers and nothing else (standalone-windows, debug-logging-§12, performance-§4). The general shape — an argument added to a shared function, and the call sites that keep their old arity — applies to any additive-only library seam: **the addition is only additive for the library**, and a caller that silently keeps the old behavior is exactly what "no consumer changes" was supposed to mean and, here, did not.

66. **Moving a TOC line without reading its comment** — reordering the file listing on the strength of what looks tidy, past a comment that says the position is **load-bearing** and names what resolves there. This is the one anti-pattern on the list whose whole failure surface is a person's attention rather than a call site, and it is here because of how it fails: a media seam dropped below `core\Constants.lua` means `FONT_MONO` resolves against a seam that has not loaded, every window in the addon draws in the client's default font, and **nothing errors** — no lint, no test, no red. It is also why the annotation is a MUST rather than a courtesy (`toc-file-§5`): an unannotated load-bearing line makes this anti-pattern unavoidable rather than merely available.

67. **A placeholder, invented, or borrowed `X-Curse-Project-ID`** — a distribution id written into a TOC to satisfy a field, in an addon that is not published. It does not fail loudly and it does not fail locally: the packager takes the id at face value and uploads **this** addon into whatever project the number names, which is somebody else's. The field is simply **omitted** until the addon is published, with a one-line comment in its position saying so, and the omission is then compliant and needs no deviation row (`toc-file-§1`).

68. **A General page whose first tab is not `Master controls`** — or that has no strip at all, or that scatters enable / visibility / scale / alpha / lock / debug / the two resets across three pages. The rows exist in every addon; what differs is where each one landed, so the player relearns the same six settings nine times. The tell is a General page whose first tab is named after a feature (`Bars`, `Capture`, `General`) rather than after what the tab is for (`options-ui-§15`).

69. **A schema row with no `group`** — a row that belongs to no section, on a page that therefore cannot draw a strip. It fails quietly in the worst possible way: delete the flow engine's untabbed fallback and the page renders blank under an empty strip, because the row matches no tab and every tab has no rows. The library reports it and degrades; the fix is the missing field, never a re-added fallback (`options-ui-§13`).

70. **A layout number read off a state-dependent measurement** — packing a wrapped tab strip by the height of whichever tab happened to be selected. The measured input differs by state, so the geometry differs by state: rows separate, the reserved band grows, the content panel below moves and resizes, and it heals the moment the player clicks another tab, which is what makes it read as a rendering glitch rather than as arithmetic. **Nothing fails**: a headless harness that answers one height for every atlas cannot see it, and that is exactly how it shipped. Measure once, from a state nothing can change, and assert the invariant rather than the mechanism (`options-ui-§13`).

71. **A hand-rolled section heading** — a colored full-width `Label` standing in for the shared `Heading`, drawn because the flow engine emitted no heading where one was wanted. It is the right instinct and the wrong tool: two heading looks on one canvas, and the second one is invisible to every rule written about the first. The heading is declared by the row (`subgroup`), and the widget is the one everything else uses (`options-ui-§7`).

72. **A bounded box around controls that already sit in the chrome band** — an inline group drawn around the create/edit block above a tab strip. The band is already delimited by its divider and by the content panel's top edge, so the box is a second boundary for the same edge, and it costs the controls inside it the width and the vertical rhythm the rest of the page keeps. Its cousin is the box drawn around a whole tab's contents, which draws a border around the thing the tab strip already framed (`options-ui-§14`).

73. **A hand-written font, border or bar control group** — six rows typed out where the composer emits them, and typed out slightly differently in each of five addons: color before flags here, no shadow there, *Font Outline* in one and *Font flags* in the next, thickness in px on one page and unlabeled on another. Each copy is defensible; the set of them is the drift the shared library was extracted to end, and the day the group grows a row it grows in one addon (`options-ui-§16`). What this names is a hand-written **copy of a block**, told by the companions it carries; a lone shared-media row with none of them — the addon-wide **broadcast meta row** — is not this, and §16 states the bounds it keeps instead. A library-absent stub **MUST NOT** carry such a copy either: its composers answer an empty row list, and a host verb that must still write a composed row on that load writes through the Schema seam's declared `writeThrough` path list, which is data, or refuses with the library-absent line (`options-ui-§1`).

The control the player is told is inert is the one still deciding the opacity they are looking at. Say it in the tooltip; leave the swatch live (`options-ui-§17`).

75. **Paired up/down arrow buttons where the list's order is the setting** — two 16px chat-scroll textures per row, a click per position, no indication of where an item will land, and a different pair of arrows in every addon that grew one. They also encode a **swap**, so a move of four positions is four writes and four re-renders instead of one splice. The shared reorder widget exists, is already vendored in every addon, and owns the handle, the ghost, the insertion line and the boundary clamp (`options-ui-§18`).

76. **A widget-type re-registration living inside an addon** — a private `core/LSMPatch.lua` calling `AceGUI:RegisterWidgetType("LSM30_Border", wrapper, AceGUI:GetWidgetVersion("LSM30_Border") + 1)` off a `PLAYER_LOGIN` frame to win the version race. The tell is the **target**, not the call: `AceGUI.WidgetRegistry` is process-global, so the addon is not restyling its own dropdown, it is restyling every dropdown in the client — and with five addons doing it, each wrapper closes over the previous one and the outermost is whichever addon loaded last, five deep. **Nothing goes red**: every suite loads exactly one copy, registers once and passes, and load order is not a thing a headless harness has. Re-registration belongs to `LibKa0s`, idempotent behind a sentinel; a per-instance fix belongs at the addon's own creation site, leaving the registry alone (library-stack-§9). #8 still sanctions `RegisterWidgetType` for a **new** name the addon defines — this is about where the call lives, not whether extending beats forking.

The README is the addon's only player-facing document and the page a stranger judges it by; machine-shaped prose is most visible there. Scope is the README alone — `docs/`, `CLAUDE.md` and code comments are contributor surfaces and are deliberately exempt (documentation-§1).

The same file is also the minimap button's and the broker object's icon, so getting it wrong is wrong in three places (`toc-file-§1`, `launcher-§4`). Two shapes of addon are reached: one with **no `profile` section**, whose global reset empties the account-wide store wholesale and takes the row with it; and **any** addon whose page-scoped Defaults button rewrites every Master-controls row that declares a `default`.
